# band-sheets

Successor to `../sheet-for-player`: per-instrument sheet editor (chords+lyrics / melody / drums for MVP), stored as plain-text files in the user's own Google Drive. Scope, principles and milestones live in `docs/requirements.md` — read it first; this file is conventions/gotchas.

## Stack conventions

- React + TypeScript + Vite, **Vitest (not Jest)** — deliberate switch from sheet-for-player: one config (`vite.config.ts`), no separate `tsconfig.jest.json`, and Storybook 10's addon already runs on Vitest.
- `vite.config.ts` defines two Vitest projects:
  - `unit` — jsdom, `src/**/*.test.{ts,tsx}`, setup in `src/test/setup.ts` (jest-dom matchers + RTL cleanup). `npm test` runs only this. Test APIs are imported explicitly from `vitest` (no globals).
  - `storybook` — every story run in real headless Chromium via `@storybook/addon-vitest`. `npm run test:storybook`; needs the devcontainer's Playwright browsers.
- `test.maxWorkers: 2` is intentional: full-suite runs repeatedly crashed WSL in sheet-for-player. Investigating that is a low-priority backlog item; do not "fix" it by deleting tests.
- E2E tests are in `e2e/` (Playwright, `npm run e2e`, starts the Vite dev server itself).
- Lint is oxlint (`npm run lint`), format is Prettier (`.prettierrc`: single quotes, semicolons, trailing commas).
- Use `import.meta.dirname` in config files, not `__dirname` (Vite 8 warns about the latter).

## Carried over from sheet-for-player (apply by default)

- Pure functions first, TDD'd in `src/lib/`, thin components on top.
- CSS Modules per component + color tokens in a `theme.css`; never raw colors in component CSS.
- Anything parsed into a structured renderer argument (pitch, duration, time signature…) must pass a strict format check before reaching the renderer — VexFlow throws uncaught errors on half-typed input.
- One user action touching two fields → one combined update, one `onChange` (two sequential `onChange` calls lose the first).

## UI/UX process

Before building any editor or view screen, sketch it with **Claude Design** (Artifact `design` type) and get the user's agreement. Each editor screen has one purpose only (lesson from sheet-for-player's crowded single-screen form).

## Source layout

**Rule: the ChordPro text is the single source of truth.** `App` (M7: the editor for ONE song, hosted by `screens/EditorScreen`; props `songId`/`initialText`/`baseVersion`/`headerStart`/`headerEnd`/`onTextChange`/`viewing`/`onEnterView`/`onExitView`/`viewBackLabel`, always remount with `key`) holds one `text` string; `song = useMemo(() => parseSong(text))`. `Root` owns the hash route (`lib/route.ts`): `#/` list, `#/new` (→ `replaceState` to `#/edit/<new id>`), `#/edit/<id>`, `#/view/<id>`; `#view`/empty/unknown → list. `Viewer` is mounted ONLY while viewing (`key={songId}`, in an `EditorErrorBoundary`); from the editor the viewer is `#/view/<id>` (`pushState`, reads the draft); from the list/URL it is `ViewerScreen` (no draft created). The editor tree stays mounted but `hidden` while viewing. The viewer only reads `song`, never writes `text`. Editor B (`TextEditor`) passes the textarea value through untouched; everything else (editor A, song info, palette) does `song → serializeSong → one setText`, which normalizes the text (accepted). Switching A ⇄ B never transforms anything.

## Gotchas

- M7 Drive (details: `docs/m7-plan.md` 実績, `docs/m7-drive-findings.md`, `docs/m7-decisions.md`):
  - File extension is `.bandsheet`, Drive mimeType `text/plain` — custom format, never call it `.chordpro`.
  - Scope is `drive.file`: the app sees only items it created itself.
  - No conditional update in Drive v3: saving is check-version-then-write (`getMeta` → compare with base → write); the small race in between is accepted. Always `getMeta` before writing: trashed files are still readable/writable (trashed = notFound). `saveSong` on a missing/trashed file returns `missing` and creates NOTHING; the editor asks 「新しく保存しますか？」 and only on confirm (inside the click, `ensureToken()`) calls `recreate` with the same songId; cancel keeps the draft; rename fails with notFound, never re-creates. Never retry `create` on 5xx (duplicate files); rateLimit is retried.
  - GIS: call `ensureToken()` inside the user gesture BEFORE any `await` (else the popup is blocked); silent renewal uses `prompt: ''` (default is `select_account`); check `hasGrantedAllScopes` for `drive.file`. In Testing mode the grant expires after 7 days and the consent screen reappears.
  - `useSongLibrary` backfill re-reads drafts and `base` AFTER the `loadRemote` await and touches nothing if a draft is unsaved or changed meanwhile. Same-songId duplicate files: one stable owner keeps the songId (cached owner, else smallest fileId), the rest are `drive-<fileId>`. A draft of a Drive song with no `base` saves against a provisional base from the list's `fileId`.
  - `signOut` keeps drafts and unsaved songs (only Drive cache and tokens go). `App` reports text changes synchronously (not in an effect), otherwise Ctrl+S right after typing saves stale text.
  - Without `VITE_GOOGLE_CLIENT_ID` (`.env.local`, see `.env.example`, `docs/m7-google-setup.md`) the app runs local-only (`unconfigured`, GIS never loaded). `vite.config.ts` pins port 5173 + `strictPort` (OAuth origin). Publishing needs the origin added to the OAuth client (and a CSP allowing `accounts.google.com` / `googleapis.com`).
  - e2e uses fake GIS/Drive (`e2e/support/fakeDrive.ts`, `page.route`; never reaches Google) on its OWN dev server, port 5174 (`reuseExistingServer: false`, fake client ID). Never reuse or kill a user's server on 5173.
  - Tablet song list is chosen by `(hover: none) and (pointer: coarse)`.
- `vite.config.ts` sets `server.host: true`: in the devcontainer `localhost` resolves to `::1`, so Vite's default binds IPv6 loopback only and VS Code's port forwarding (which connects to 127.0.0.1) fails with ECONNREFUSED — the browser just spins.
- `App` takes an optional `storage` prop; stories / unit tests pass `createMemoryStorage(...)` so they never share the browser's real localStorage (Storybook runs all stories in one origin).
- e2e: clear localStorage with `page.evaluate` + `reload`, not `addInitScript` (that would also wipe the draft on the persistence reload). A key must be set before diatonic chips appear in `ChordPopover`.
- The a11y check (`a11y: { test: 'error' }`) enforces heading order: the chart panel has a visually hidden h2 so editor section h3s don't skip a level.
- alphaTex: a `\section "A"` line directly followed by a bare note (no `:N`/`.N`) swallows that note as the section's second argument — always write `:N` (or `.N`) before the first beat of a section, even if the duration hasn't changed. `.N` glued to a pitch (`C4.4`) is sticky across beats and bars exactly like a `:N` token (verified against alphaTab 1.8.4, see `melody.ts`'s spec comment).
- alphaTex slurs (alphaTab 1.8.4): note effect `slur "<id>"` (or `slur ident`) on the origin and again on the destination note. The importer's id map is per staff and never cleared within it, so an id reused in the same part re-points the earlier slur — `serializeMelody` uses `"<section label>-<n>"`; always pass the label.
- `PartScore` (alphaTab) renders only track 0 by default — pass the track indexes you want explicitly (`api.tex(tex, trackIndexes)`), or a multi-part song only shows its first part.
- alphaTab `player.scrollMode` must be `Off` in every app component that creates an `AlphaTabApi` (issue #1; already set in `PartScore` and `SectionScore`): the default scrolls the page/container on playback and cursor updates.
- `PartScore` draws drum (percussion) staves with ALL stems/beams up: alphaTab 1.8.4 otherwise picks the direction per beam group from staff position, so BD/SD/FT groups hang below. Done at render time only — `api.scoreLoaded` (fires after import, before layout) runs `percussionStemsUp(score)` (`components/PartScore/percussionStems.ts`), setting `beat.preferredBeamDirection = rendering.BeamDirection.Up` on every beat of `staff.isPercussion` staves. The stored alphaTex is never touched (no per-beat `{beam up}`); melody staves keep alphaTab's automatic direction. Note `BeamDirection` is exported under alphaTab's `rendering` namespace, not `model`.
- Bravura (the music font `MelodyStaff`/`PartScore` draw with) is registered as a `@font-face` via `injectBravuraFontFace()` (`components/PartScore/bravuraFont.ts`); call it yourself when rendering a staff component on its own, since it's otherwise only a side effect of importing `PartScore`.
- jsdom (unit tests) has no `ResizeObserver` and alphaTab's `AlphaTabApi` throws synchronously outside a real browser; `App`'s `Tabs` keeps every tab panel mounted (just `hidden`), so `MelodyEditor`/`MelodyStaff`/`PartScore` mount on every `App` render even off the メロディ tab. `src/test/setup.ts` stubs `ResizeObserver` globally, and `PartScore` catches the `AlphaTabApi` constructor's exception into its existing `error` state (deferred via `queueMicrotask` so it isn't a synchronous `setState` inside the effect, which oxlint's `set-state-in-effect` flags).
- `MelodyEditor` owns the editor's ONE aria-live region (M8): it computes the text (state changes like 「8分音符」 via `stateChangeMessage`, note descriptions via `announcement`, lyric-op messages) and passes it to `MelodyStaff`'s `liveMessage`; don't add other live regions in the melody tab (LyricsPanel's counter is deliberately not live). It also uses the part's preamble `\ts`/`\ks` over the song meta (M11) — use its effective `ts`/`keySig`, not `song.meta`, for anything section-related.
- Storybook `userEvent.keyboard('.')` does not produce `code: 'Period'` (the editor maps keys by `e.code`); write `'[Period]'`.
- alphaTex effect order (M5, verified against alphaTab 1.8.4): a note effect (`{g}` ghost, `{ac}` accent, `{hac}` heavy accent) goes right after the note name, before the duration; a beat effect (`{tu N}`, `{d}`) goes after the duration (or after the closing `)` for a chord). Mixing the two into one `{}` after the duration is also accepted on read (M4's `C4{d t lyrics}` form), but `serializeDrums`/`serializeMelody` always write the note-effect form.
- `{tu N}` must be written on EVERY beat of a tuplet (alphaTab has no group-start/end marker) — and alphaTab does not validate that a bar's total duration matches its time signature, so a malformed tuplet or bar can import silently; `groupsFitBars` / the parsers' own bar-length checks are the only thing catching this.
- `\tf` (triplet feel / shuffle) persists into later bars and sections in alphaTab. A section without its own `\tf` line is read as inheriting the last `\tf` in part-body order (an earlier section's, or the part preamble's) — matching alphaTab's actual behavior — and the editor writes that inherited value explicitly into the section the first time it's edited there. Conversely, writing/changing a `\tf` auto-inserts the OLD inherited value into every later `\tf`-less section whose rendering would otherwise change (m5-review.md R2, `drumPart.ts`'s `chartOrder` param). The first beat right after a `\tf` line still needs an explicit `:N` (same rule as after `\section`).
- Drum alphaTex: a rest is lowercase `r`; uppercase `R` is read as a percussion instrument name (and is simply unknown, since it's not in `DRUM_KIT`), not a rest.
- Storybook stories that need a Shift+click (e.g. `DrumPads`' Shift+click = toggle on the previous beat) must use `fireEvent.click(el, { shiftKey: true })` — Testing Library's `userEvent.click` does not set `shiftKey`.
- `DrumEditor` owns the drum tab's ONE aria-live region (same M8 pattern as `MelodyEditor`): it computes the text and passes it to `DrumStaff`'s `liveMessage`; don't add another live region under the ドラム tab.
- A rejected command's visible error text (`data-testid="editor-error"`, both editors) is deliberately NOT `role="alert"` — the live region is the only announcement, so a rejection isn't read twice (m5-review.md R6). Each editor's `say(msg)` re-announces even when `msg` repeats the previous live text, by toggling a trailing U+00A0 on/off (screen readers don't announce an unchanged live region).
- `tuplet.ts` ↔ `melody.ts` import cycle: `tuplet.ts` uses `melody.ts`'s `DURATION_TICKS`/`Duration` as values (including at module-init time), so `melody.ts` must only `import type` from `tuplet.ts` (never a value import) or the cycle breaks at runtime.
- M6 viewer + alphaTab (details: `docs/m6-alphatab-findings.md`, `docs/m6-plan.md`):
  - `SectionScore` turns off `EffectMarker`/`EffectTripletFeel`/`BarNumber`/`TrackNames`/`EffectTempo`/title elements: rehearsal numbers are an HTML gutter, bar numbers (song-wide, `firstBar`) and Shuffle are drawn by us from `boundsLookup`. `TripletFeelEffectInfo` has `hideOnMultiTrack` and draws only on the first track, so alphaTab would put Shuffle on the melody staff.
  - alphaTab always draws a 「rendered by alphaTab」 line under each render regardless of settings: `SectionScore` clips it (min of last system bottom and the text top) and the viewer shows ONE credit at the end.
  - `SectionScore` also reports failures via `onError`; `ViewerSheet` treats it as a layout tick (failed section = `score-error:<key>` unit, `ready` stays reachable). After a pointer click on any button outside the modal drawer (incl. inside non-modal popovers, which stay open) `Viewer` returns focus to the sheet so pedal Space/Enter page.
  - `postRenderFinished` can fire twice per `tex()`: `onLayout` must tolerate repeated calls; consumers act on the latest value.
  - `boundsLookup` coordinates (`staffSystems[].realBounds`, `bars[].visualBounds`) are container-based; a gap of 10–15px between systems is in no `realBounds`; left/top margin is a constant 35px regardless of `display.scale` (we set margins L/R 12, top 6, bottom 0). Change zoom via `settings.display.scale` + `updateSettings()` + `render()`.
  - `display.justifyLastSystem = true` or a section's last system stops at ~55% width. `core.enableLazyLoading = false` is required because page mode hides content with `transform`/cover, not scroll.
  - Per-section docs need carry-over from the whole-part import: last `\ts`/`\ks`/`\clef`, inherited `\tf` (drums), and `:N` before the first beat. Difference to the whole-part read: a bare note right after `\section` is swallowed as the name's 2nd argument there, but a per-section doc (with `:N` added) shows it as a note. With two tracks of different `\ts`, the master bar takes the later track's, so use each part's own time signature.
  - `\tf` is per master bar: `ShuffleMark` is ours (Bravura glyph over the drum staff's section start; `'none'` after a shuffle block → 「Straight」). To make alphaTab leave a band above the drum staff, `SectionScore` adds invisible 3-line `beat.text` on the first drum beat at render time (relies on alphaTab internals; a hand-written `{txt}` then renders below the band).
  - `Viewer` listens for keys on `document`: it must be UNMOUNTED when leaving (else pedal keys leak into the editor). `ViewerToolbar` goes compact below 1400px (`ResizeObserver` on the bar: page-nav/font controls move to the drawer, score chips into a 「パート ▾」 popover). Tap-zone hover/active styles only under `@media (hover: hover)` (touch leaves them stuck).
  - Viewer's ONE live region: announces 「n / N ページ」 once when the page count changes, only in page mode (not scroll/auto, not during rendering); don't add others. Repeated messages toggle a trailing U+00A0 (same as the editors). Count-in is `aria-hidden`.
  - Bar numbers: system boxes grow UPWARD to include the number's top (`min(realBounds.y, number top)`, number box height fixed at 1.5 system gaps); the first system's overflow shifts the whole overlay down (`Overlay.shift` in `SectionScore`'s `measure`). Shuffle marks are per drum track: `sectionScoreTex` returns `shuffleMarks: {track, shuffle}[]` (→ `SheetScore.shuffleMarks` → `SectionScore`), each band located per track (invisible row between the system above's bottom and this system's top).
  - A failed score render is its own pagination unit (`score-error:<key>`, whole frame) and still carries the section's bars for the auto-scroll timeline (`ViewerSheet`'s `measure`); the preceding chart's last line keeps `keepWithNext`.
  - Viewer focus: pointer clicks on toolbar / auto-scroll / play-mode buttons return focus to the sheet viewport (root click handler; skips keyboard clicks `detail===0` and clicks inside dialogs), and closing the settings drawer returns focus to the viewport too, so pedal Space/Enter page.   - ▶ stays disabled until `layout.ready` (`AutoScrollBar` `playDisabled`; `play()` also refuses before ready, live text 「譜面を準備中です」). Count-in follows speed changes (`beatSec` and elapsed re-scaled mid count-in).
  - `ViewerChartBlock` takes `ariaLabel` because a repeated label would create duplicate landmark regions (`landmark-unique`).
  - Transpose UI (`TransposeControl`): side buttons show the RESULTING value, the middle value is display-only, 「原曲キーに戻す」 is disabled (not hidden) at 0; announced via the viewer's one live region (`changeTranspose` → `say`). The bar is inline-wide only from `TRANSPOSE_INLINE_FROM_PX` (2000; the group needs ~600px), otherwise a 「移調 ▾」 popover; `COMPACT_BELOW_PX` is 1600 (was 1400) because the extra button made the bar overflow.

## Audio analysis spike (spikes/analysis)

Spike 0 of the audio-import feature (`docs/audio-import-architecture.md` §8.2; plan `docs/audio-spike0-plan.md`, review `docs/audio-spike0-review.md`). Synthesizes wavs from band-sheets songs with alphaTab, writes ground-truth JSON, and scores analyzer output. Outside oxlint, prettier, `tsc -b` and the app's `npm test`; `out/` is gitignored (regenerate in seconds).

- `render/` (TypeScript, run with tsx in the devcontainer) and `py/` (Python 3.12 in the Docker image `band-sheets-analysis`, pinned by digest + `requirements.lock.txt`).
- Render all variants to `spikes/analysis/out/`: `docker exec -u node -w /workspaces/band-sheets/spikes/analysis band-sheets npx tsx render/cli.ts`
- TS tests: `docker exec -u node -w /workspaces/band-sheets band-sheets npx vitest run --config spikes/analysis/vitest.config.ts`
- Python: build once with `docker build -t band-sheets-analysis spikes/analysis/py`, then `docker run --rm -u 1000:1000 -e HOME=/tmp -e NUMBA_CACHE_DIR=/work/out/.numba-cache -v <repo>/spikes/analysis:/work -w /work band-sheets-analysis python py/check_alignment.py` (also `python py/run_all.py`, or `python -m unittest discover -s py/tests`). `NUMBA_CACHE_DIR` lives under gitignored `out/` so the ~25 s numba compile survives across containers.
- Soundfont: `fetch-soundfont.sh` downloads MuseScore_General.sf3 (SHA-256 pinned) into gitignored `soundfonts/`; alphaTab can't read sf3, so `render/sf3ToSf2.py` (run in the Python image: `python render/sf3ToSf2.py`) converts it to `soundfonts/MuseScore_General.sf2`, which `renderAudio.ts` uses for the `musescore` variants.
- `py/check_alignment.py`: only enforced `mix == "piano"` variants FAIL (exit 1); everything else is WARN (exit 0) — that split predates T15. The T15 (R9) fix was reversing the comparison direction for `whole` (sustained) onsets: each detected onset is compared with the nearest truth beat. Known gap: it misses an offset of exactly a whole number of beats. `pianoGainDb < 0` variants use a lower chord-share threshold (80 %, `CHORD_MIN_SHARE_QUIET`, observed 89.8 %), which only silences WARNs on non-enforced (`mix: full`) variants.
- Held-out variants (`heldOut`): `run_all.py` skips them by default; `--include-held-out` includes them; combining it with `--dsp-config` raises `HeldOutError` (never tune on held-out). `report.py` shows them in a separate table.
- `py/midbar.py` makes level "M" mid-bar-start variants (`derived/manifest.trim.json`); `dsp-phase0` is the always-phase-0 baseline for judging the downbeat rule. Judge the downbeat rule on level M (dsp-v1 1.000 vs dsp-phase0 0.000), not on L0/L2 where both score the same; all M variants derive from tuning songs (no held-out M). Level M section F = 0.000 because the first COMPLETE bar is treated as bar 0, so boundaries land exactly one bar late and miss the 1-bar scoring window by ~11 ms (known; spike 2).
- CI: the separate `spike-analysis-py` job runs the spike Python unit tests (`python -m unittest discover -s py/tests`).
- alphaTab `\tf` only carries to later bars when the DRUM track is first: render Drums first. Take melody/drum truth times from alphaTab's MIDI note-ons, not from the score.
- alphaTex tracks default to program 25 (guitar) unless a program is set.
- A missing drum bar is silently filled by alphaTab (`bar.isEmpty`); `truth.ts` rejects it.
- Licenses: soxr/libsndfile (LGPL) and certifi (MPL-2.0) are in the local Python image only; never ship them in the app.

## Git workflow (GitHub Flow, decided 2026-10-10)

- `main` is what's deployed: every push to `main` publishes to GitHub Pages (`deploy-pages.yml`). It is protected — no direct pushes; changes land through a PR whose `CI` check (`ci.yml`: lint, prettier, `tsc -b`, unit tests, build) passes. Solo project: no review approval required.
- Work on a short-lived branch per task, named `<type>/<issue#>-<slug>` (issue number when there is one): `feature/…`, `fix/…`, `spike/…` (audio analysis spikes), `docs/…`, `chore/…`. Open the PR with `gh pr create`, put `Closes #N` in the body, merge with a squash merge once CI is green, then delete the branch.
- Storybook and e2e tests are not in CI (they need the devcontainer's browsers): run the affected ones locally before opening the PR.
