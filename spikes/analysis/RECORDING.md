# 録音の渡し方（スパイク 2）

録音（音声）とコードの書いた .txt を、受け入れフォルダに入れるだけです。あとは 1 コマンドで取り込みます。

## 1. 受け入れフォルダ

WSL: `/home/mrk5/projects/band-sheets/spikes/analysis/recordings/inbox/`
Windows のエクスプローラー: `\\wsl.localhost\Ubuntu\home\mrk5\projects\band-sheets\spikes\analysis\recordings\inbox`

（このフォルダは git に入りません。曲名がファイル名でも大丈夫です。取り込み後は匿名の名前（曲は `rec-01` …、1 回の演奏は `rec-01-a` …）に変わります。）

## 2. DAW（Cakewalk Sonar）からの書き出し

- **おすすめ**: 書き出す範囲を「1 小節目の頭ちょうど」から始めて WAV で書き出す。`.txt` に `開始: 0秒` と書く。
  - 弱起（1 小節目の前に数拍ある）の曲は、弱起の最初の拍から書き出し、`弱起: 1拍` と `開始: 0.484秒`（= 弱起の拍数 × 60 ÷ bpm）を書く。
- 録音にクリックのカウント（1 小節目の前の空きクリック）が入っているときは `カウント: 2小節` と書けば、クリックから 1 小節目の頭を自動で合わせます（`開始:` より優先。弱起はそこから数拍さかのぼります）。
- `開始:` を書いた場合はその位置を使います。実際の最初の音と 1/4 拍より大きくずれていると警告だけ出します（1 小節目より前に音がある場合は、`開始:` で 1 小節目の頭を指定してください。最初の音に合わせたいときは `--fit-start`）。`開始:` を書かなければ最初の音から自動で合わせます。
- 位置を揃えられないとき: `開始:` を書かなければ、音の最初の立ち上がりを 1 小節目の頭（弱起ありなら弱起の最初の拍）とみなします。取り込みのとき検出した位置が表示されるので確かめてください。
- bpm は DAW のプロジェクトのテンポ。
- WAV は 16/24 ビット整数・32 ビット浮動小数、モノ/ステレオ、44.1/48/96 kHz どれでも可（自動で モノ・44.1 kHz に変換）。m4a / aac は読めません（WAV か mp3 / flac にしてください）。
- マキシマイザーを掛けるときは、**掛ける前と後の両方**を書き出すのがおすすめ（最低限は掛けた後だけ）。

## 3. ファイルの名前

同じ名前でそろえます（名前は何でも可）。**同じ曲を別の弾き方で録ったとき**は、名前の `_` より前を同じにします（例: `曲A_いつも.wav` + `曲A_いつも.txt` と `曲A_3度あり.wav` + `曲A_3度あり.txt`）。`_` より前が同じなら同じ曲として扱われます。`_` が無いときは名前全体が曲の名前です。

| ファイル | 意味 |
| --- | --- |
| `名前.wav` | 音声（マキシマイザー前。1 本だけならこれ） |
| `名前.max.wav` | 同じ録音のマキシマイザー後（あれば） |
| `名前.txt` | コードの書いたファイル（必須。2 本の音声で共通） |
| `名前.mid` | 弾いた MIDI（任意。保存するだけ） |

`.max.wav` がある 2 本も、`_` より前が同じ複数の録音も、同じ曲として扱われ、ホールドアウトかどうかは同じです（1 つの曲を開発用とホールドアウトに分けません）。評価専用は曲ごとに自動で決まります（曲の番号 `rec-NN` が偶数ならホールドアウト。解析の前に決まり、記録されます）。

## 4. .txt の書き方

```
bpm: 124
拍子: 4/4
キー: C          （任意）
弾き方: a        （a〜e。下の表）
弱起: 1拍        （任意）
開始: 0秒        （任意。1 小節目の頭の秒数）
クリック: あり   （任意。既定はあり）
マキシマイザー: あり   （任意。音声が 1 本のときだけ使う）
| C | Am7 | F | G7 |
| C . Em . | F G |
```

- `|` で小節を区切る。1 小節に書いたコードは小節を等分する（2 つなら半分ずつ、4 つなら 1 拍ずつ）。`.` は「前のコードのまま」。
- `N.C.`（または `N`）はコード無し。`#` で始まる行はメモ。英語の項目名（bpm / time / key / style / pickup / start / click / maximizer）でも可。
- コード名は `C` `Dm7` `G7(#9)` `Bm7b5` `C/E` のように書く。読めないコードは「何行目の何が読めないか」が表示されます。

### 自分流の書き方(受け付ける形)

- **ダッシュ + 角括弧**: `|[Dm]---[Am7]- --[Abm7]--|` のように、コードを `[ ]` で囲み、その後ろの `-` 1 つが八分音符 1 つぶん。空白は無視。上の例は Dm 3・Am7 3・Abm7 2(4/4 は 1 小節 = 八分音符 8 個)。
  - `| [F#m7] |` のようにコード 1 つだけの小節は小節全体。`| [F#m7/B]---- [B]----|` は 4 + 4。
  - 1 小節の `-` の合計が拍子と合わないときは、行番号つきのエラーになります。ただし、その小節のどのコードにも `-` が無いときは等分(`| [C][G] |` は半分ずつ)。
  - 1 行に小節が複数あっても、行の頭と終わりの `|` が無くても可。小節の頭の `-` は前の小節の最後のコードの続き(その小節の 8 個に数える)。最後の `|` より後ろの文字、`-- 名前 --` のような区切りの行、`[|]` は無視。
  - 従来の `| C . Em . |` もそのまま使えます。
- **弾き方の複数指定**: `弾き方: b,e`(`,` `、` 空白区切り)。最初の文字(b)がその録音の名前(`rec-NN-b`)になります。
- **キー不明**: `キー: ?` と書くと調の評価は行いません。
- 改行が CRLF でも、行末の空白があっても可。`弱起: なし` は 0 拍。
- **歌詞つきのコード譜**(`[CM7]歌詞[D]歌詞…`、小節線なし): 拍の位置が分からないので **順序だけの正解**(`timing: "sequence"`)になります。歌詞は捨て、コードの並びだけを保存。拍ごと・小節ごとの評価は行わず、レポートに「コードの順序だけの正解」の小さい表(コード名なし・数字のみ)が出ます。指標は、語彙の対応(`map_vocab`)を通して連続する同じコードを 1 つにした列どうしの LCS と類似度(1 - 編集距離 / 長い方の長さ。ルートだけの版もあり。移調は考慮しない)。
  - 同じファイルに小節線つきの行と歌詞つきの行が混ざるときは、全部のコード行に小節線があれば小節のタイミングを使い、そうでなければ(歌詞つきの行が 1 つでもあれば)順序だけの正解になります。
  - ファイルの中に読めない行(どの形でもない行)があると、行番号つきのエラーになります。

弾き方（a〜e）。録音の種類を表す記号です（開発用かホールドアウトかは記号では決まりません）。

| 記号 | 弾き方 |
| --- | --- |
| a | いつもの弾き方（右手 = 空虚 5 度 + メロディ） |
| b | 同じ曲を 3 度入りの和音（右手に 3 度を含む）で弾く（メロディは要らない）。a の曲と同じ曲名の組にする |
| c | ゆっくりの曲（70〜90 BPM 程度） |
| d | 弱起の曲 |
| e | 離れた部屋の録音 / ギターのストローク（任意） |

## 6. コード進行だけを渡す（録音なし）

録音が無くても、よく知っている曲の **コード進行だけ** を書いてもらえれば、それをピアノで鳴らした合成音（調つき・転調つき）を作って、キー追跡やコード理論の評価に使います。

**置き場所**: WSL `/home/mrk5/projects/band-sheets/spikes/analysis/recordings/charts/`
Windows のエクスプローラー: `\\wsl.localhost\Ubuntu\home\mrk5\projects\band-sheets\spikes\analysis\recordings\charts`（`wslpath -w /home/mrk5/projects/band-sheets/spikes/analysis/recordings/charts` でも出ます）

1 曲 1 ファイルで `名前.txt`（名前は何でも可）を置きます。書き方は 4 章の .txt と同じです。違いは次のとおり。

```
bpm: 124
拍子: 4/4
キー: C          （任意。書くと調の評価ができる）
弱起: 1拍        （任意。4/4 だけ）
| C | Am7 | F | G7 |
| C . Em . | F G |
キー: D          （小節の行と行の間に書くと、次の小節から D に転調）
| D | Bm7 | Em7 A7 | D |
```

- `弾き方:` と `開始:` は要りません。録音も要りません。
- 曲の途中の `キー:` は「その次の小節から」その調、という意味です（何回でも可）。
- 1 小節に書いたコードは小節を等分します（`.` は前のコードのまま）。`N.C.` の小節は、鳴らす側では前のコードが続きます（正解も同じ）。
- 9th・13th・add9・6 などは鳴らせないので自動で簡単な形にします（`Dm9`→`Dm7`、`G7(#9)`→`G7`、`C6`→`C`。正解もその形）。簡略化した個数は実行時に表示されます。
- メロディは要りません（コードだけ）。曲名やアーティスト名も書かなくて大丈夫です。メモを書くときは `#` の行に。

**歌詞つきの形（ChordWiki など）**
- ChordWiki などの歌詞つきの形（`[C]あいうえ[G]おかきく` のような、歌詞の途中に `[コード]` が入った形）を **そのまま貼ってよい** です。小節線（`|`）も `-` も要りません。
- コードの長さは **歌詞の文字数から自動で決めます**（次のコードまでの文字数に比例。行末のコードは行末まで）。1 行は 2・4・8 小節のどれかに、コードは 2・4・8 拍に丸めます。歌詞のない行（コードだけの行）は 1 コード = 1 小節です。
- 原曲と多少違っても大丈夫です。合成では **このコード譜が正解** になります（原曲どおりである必要はなく、現実的な進行であればよい）。
- **決まり（2026-10-17 ユーザー判断）**: ChordWiki などのコード進行を **合成音源の入力** にするのは可です（譜の進行 → 合成音 → 精度の試験。正解は作り方からその進行そのもの）。目的は王道進行・小室進行・丸サ進行・コンファメ進行などの現実の進行の例です。**不可**: ChordWiki・楽器.me・U-FRET のコードを、市販の録音（配信・CD）の「正解」にすること、大量のコード譜からの統計・事前分布、学習済みモデル。注意: 調整した重みが、選んだ譜の進行に寄る可能性があります。
- **歌詞は保存しません**（内部ファイルには時刻つきのコード・キー・メタ情報だけが残ります）。
- `Aメロ`・`[Verse]`・`-- 名前 --`・`{title: …}`・歌詞だけの行は無視します。`N.C.` は無音扱い、`(` `)` `→` `×2` など読めないものは読み飛ばして警告を出します（コード内容は表示しません）。`bpm:` が無いときは 120 にして警告します。
- 小節線つきの書き方でも、1 小節の長さが拍子と合わないときは、エラーにせず小節に合わせて伸ばし縮めして警告します（録音の .txt は今までどおりエラーです）。
- 6/8・12/8 などの複合拍子は登録だけして描画はスキップします（`skipped: compound meter`、後のスパイクで扱います）。3/4 はブロックコードだけで描画します。

**取り込みと作成**（`spikes/analysis` で。2 段階です）:

```
# 1) 読み込み・匿名の名前 chart-01 … を付ける・ホールドアウトの判定（Python 側）
docker run --rm -u 1000:1000 -e HOME=/tmp -e NUMBA_CACHE_DIR=/work/out/.numba-cache \
  -v /home/mrk5/projects/band-sheets/spikes/analysis:/work -w /work band-sheets-analysis python py/charts.py
# 2) 音の作成（devcontainer 側）→ out/charts/ に chart-NN-{block,rec,rechard}.wav と正解
docker exec -u node -w /workspaces/band-sheets/spikes/analysis band-sheets npx tsx render/chartsCli.ts
```

- 1 曲から 3 種類を作ります: `block`（毎拍の和音、L0 相当）、`rec`（録音に近い弾き方）、`rechard`（録音に近い難しい弾き方）。拍子が 4/4 以外のときは `block` だけです。
- ホールドアウトは **id の番号で自動** に決まります（chart-04, chart-08 … が最後の確認用）。解析の前に `out/results/heldout-log.jsonl` に記録されます。書き直して再実行しても同じ曲は同じ id のままです。
- 評価では、レポートに「CH」として出ます。コード名も曲名も出ません（図もコード名なし）。
- ファイルを直したら、1) と 2) をもう一度実行してください。

**プライバシー**: **手元だけ** で使います。`recordings/` も `out/` も git に入らない設定で、**git にも Google Drive にも上げません**。実行のたびに `privacy_check` が走り、曲名（ファイル名・`#` のメモ）やコード進行が git で管理されるファイルやコミットメッセージに紛れていないか確かめます（ホストでも `python3 spikes/analysis/py/privacy_check.py`）。

## 7. 鼻歌の録音（スパイク 4）

鼻歌から音符を出せるかを確かめるための録音です。**6 本**（開発用 4 本、ホールドアウト 2 本）を、普段の録音と同じく**手元だけ**で扱います（git にも Google Drive にも上げません）。

### 7.1 録り方

- **クリックはヘッドホンで聞く**。DAW（Cakewalk Sonar）やスマホの録音アプリで、メトロノーム（クリック）を鳴らしながら歌います。クリックの音は**録音に入れない**（スピーカーから鳴らさない。DAW ではクリックのトラックを書き出しに含めない）。
- **1 小節のカウントインを聞いてから**歌い始めます（4/4 なら 4 つのクリックを聞いてから 1 小節目の頭で歌う）。録音は、カウントインの前から回してかまいません。
- **モノ（1 チャンネル）**でかまいません。ステレオでも自動でモノにします。
- 書き出し: WAV の 44.1 kHz か 48 kHz（16/24 ビット）。スマホは、録音アプリの音声ファイル（wav / mp3 / flac。m4a・aac は読めないので、WAV に変換するか WAV で録れるアプリを使う）。
- 長さ・拍子: **8〜16 小節、30〜60 秒くらい、4/4**。ユーザーが楽譜を知っていて、band-sheets のメロディ画面で書ける曲にします。
- 歌い直しは**解析を走らせる前なら何度でも**可。うまく歌えなくても、歌ったとおりの録音でかまいません（直す手数も測りたいので、きれいすぎなくて大丈夫です）。

### 7.2 6 本と歌い方（記号）

| 記号 | 曲 | 歌い方 |
| --- | --- | --- |
| a | 曲 1 | 「ら」「た」など**1 音ごとに区切って**、中くらいのテンポ（100 前後） |
| b | 曲 1（a と同じ曲） | 同じ曲を**口を閉じた「ん〜」**で |
| c | 曲 2 | **ゆっくり**（70〜90 BPM）で長い音が多い曲 |
| d | 曲 3 | **速め**（16 分音符やシンコペーションのある曲） |
| e | 曲 4 | 別の曲（好きな歌い方） |
| f | 曲 5 | 別の曲。**e と f のどちらかはスマホで録る** |

- どの録音がホールドアウト（最後の 1 回だけ見る用）になるかは、**曲ごとに自動**で決まります（曲の番号が偶数ならホールドアウト。同じ曲の a と b は同じ側）。下の 7.4 の名前にすると、曲 2（c）と曲 4（e）がホールドアウトで、残り 4 本が開発用になります。解析の前に決まって記録されます。

### 7.3 .txt の書き方

録音ごとに 1 つ、同じ名前の `.txt` を作ります。`メロディ:` の行から下はすべて**正解のメロディ**です。

```
# 作り物の例（この曲名はありません）
bpm: 100
拍子: 4/4
開始: 2.4秒
歌い方: a
メロディ:
:4 C4 E4 G4 E4 |
:8 D4 F4 A4 F4 G4 E4 C5 r |
:2 B3 :4 D5 G4 |
:1 C4 |
```

| 行 | 意味 |
| --- | --- |
| `bpm:` | クリックのテンポ（4 分音符 1 拍の速さ。4/4 の場合） |
| `拍子:` | 4/4 など（省略すると 4/4） |
| `開始:` | **1 小節目の頭**が録音の何秒目か。カウントインの 1 小節ぶんを飛ばした位置です（例: 100 bpm の 4/4 で、録音の頭にクリックが 1 小節ぶん入っていれば 4 × 60 ÷ 100 = 2.4 秒）。DAW の再生位置で 1 小節目の頭の時刻を見るのが確実です |
| `歌い方:` | a〜f（7.2 の表） |
| `メロディ:` | この行から下がメロディ（行の途中から書き始めてもかまいません） |

- `#` で始まる行はメモです。英語の項目名（`start:` `style:` `melody:` `time:`）でも書けます。
- **正解のメロディは、解析を走らせる前に**書きます（歌った後で聞き直して直すのはかまいませんが、解析結果を見てからは直さない）。

**メロディのテキストの作り方**: band-sheets のメロディ画面でメロディを書き、「テキスト入力」の画面（エディタ B）で、そのメロディの部分（`\section "…"` の行の**次の行から**、音符の行まで）をコピーして貼ります。`\section` `\ts` `\ks` `\lyrics` などの `\` で始まる行は貼りません。

- 書き方（メロディ画面が書く形と同じ）: `:4` `:8` `:16` `:2` `:1` が音の長さ（以降の音符に続く）、`C4` `C#4` `Bb3` が音名（C4 = 真ん中のド）、`r` が休符、`|` が小節の終わり、`{d}` が付点、`{t}` がタイ。歌詞 `{lyrics "…"}`・コード `{ch "…"}`・スラー `{slur …}` が付いていても無視します（そのまま貼ってよい）。
- 各小節の長さは拍子ぴったりに（最後の小節だけ短くてもよい）。連符 `{tu}` は使えません（16 分の格子だけを使います）。
- 音名は、**実際に歌った高さ**で書きます（男声などで画面の範囲 C3 より低いときは、テキストで `A2` のように書いてかまいません。画面では書けなくても解析側は読めます）。
- 読めない所があると、「メロディ: 3 小節目の長さが拍子と合いません」のように教えてくれます。

### 7.4 ファイルの名前と置き場所

置き場所（WSL）: `/home/mrk5/projects/band-sheets/spikes/analysis/recordings/hum-inbox/`
Windows のエクスプローラー: `\\wsl.localhost\Ubuntu\home\mrk5\projects\band-sheets\spikes\analysis\recordings\hum-inbox`

音声と `.txt` を**同じ名前**にします。名前は `曲の番号_記号` がおすすめです（曲名は書かない）:

```
1_a.wav  1_a.txt     2_c.wav  2_c.txt     3_d.wav  3_d.txt
1_b.wav  1_b.txt     4_e.wav  4_e.txt     5_f.wav  5_f.txt
```

`_` より前が同じものが同じ曲になります（曲の番号は、名前の順に 1, 2, … と付きます）。曲名がファイル名に入っていても大丈夫ですが（取り込み後は匿名の名前になります）、番号の名前にすると上の表のとおりに揃います。
