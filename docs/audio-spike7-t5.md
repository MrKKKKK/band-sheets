# スパイク 7 T5: 合成の素材（B・V1〜V3・音が同じ組の例）

想定読者: T7〜T15 で合成の素材を採点・調整に使うエージェントと、素材が本物らしいかを確かめるユーザー。
目的: T5 で作った合成の素材の中身（分け方・数・長さ・音色・変化・弾き方）と、正解が描いた音と合うことをどう確かめたかを残す。

2026-11-15。計画は `audio-spike7-plan.md` §3.1・§4・T5 の行。素材は git に入れない（`out/chords2/`、gitignore）。ここには集計だけを書く。

## 作り方

```
bash spikes/analysis/fetch-soundfont.sh          # + render/sf3ToSf2.py（解析の image で）: P1・ベース A
bash spikes/analysis/fetch-bass-samples.sh       # ベース B・C（スパイク 6 のまま）
bash spikes/analysis/fetch-piano-samples.sh      # P2（ホールドアウトのピアノ。新しい）
npx tsx render/chords2/cli.ts [--only GLOB] [--check [N]] [--list]   # spikes/analysis から。out/chords2/ に書く
```

- コードは `spikes/analysis/render/chords2/`: `material.ts`（何を弾くか）、`voicing.ts`（どう押さえるか）、`variants.ts`（分け方・変化・種）、`pianos.ts`（ピアノの音色）、`render.ts`（音符・置き方・混ぜ方）、`truth.ts`（正解の JSON）、`check.ts`（確かめ）、`cli.ts`。
- 1 回の実行は全部で約 1 時間（548 本）。`--only` で分けて回すと `manifest.json` に足していく。
- 名前は `c2-<分け>-<組>-<変化>-s<種>`。分けの文字 `t` = 調整、`d` = 開発、`h` = ホールドアウト。`variants.ts` の `splitOfName` が名前から分けを返し、`manifest.json` の各行にも `split`・`heldOut` がある（§4 の守りが合成の数と分けを確かめるため）。
- ホールドアウトも作って `--check`（正解と描いた音の照合）まで通したが、解析器にはかけていない。開発用も解析していない。

## 弾き方（ユーザーの指摘 2026-11-15 を反映）

- 右手は和音の密集した転回形（オクターブの中、G3〜A5）。前の右手から一番動かない形を選び、手の中心へ少し引き戻す。同じ和音が続く所は右手がそのまま（`C → C/D → C/E` は右手 C・E・G のまま、左手 C–D–E）。
- 4 音の和音でベースが和音の音なら、その音は左手に任せる（`C7` は右手 E G B♭、`Am7/G` は右手 A C E、`Am6` は右手 C E F#）。3 和音は右手に 3 つとも（`C/E` は右手 C E G）。内声のクリシェは右手の 1 声だけが半音で動く（テストで固定）。
- 9 の和音（ベース = ルート）: 全部 = 右手 3-7-9・左手 1-5、5 度なし = 右手 3-7-9・左手 1、ルートなし = 右手 3-5-7-9・左手 1（右手だけでは `C9` が `Em7b5` になる形）。
- 左手は C2〜B2 のベース。ベースの楽器は書いたベースの音だけを全音符・2 分・8 分で弾く（経過音や 5 度は弾かない。5 度の見張りは lh15 の左手）。伴奏の形は種ごとに白玉・4 分・8 分のアルペジオ（ペダルで伸ばす）。

## 正解（`<name>.truth.json`）

- `chords[]`: 区間ごとに開始・終了（拍の格子の上）、`root`・`bass`（`/X`、無ければ null。♯の名前）、`text`、`quality` = `originalQuality` = 書いた種類（chords2 の語彙そのまま。「落」への写しは T4 の採点がする）。続く同じ和音は 1 区間にまとめる。
- `beats`・`sections`・`key`（曲の調。組の例は行の調を移調したもの、短調あり）、`bassNotes`（ベースの楽器の音。ピアノだけなら左手の一番低い音）。
- `chords2.segments[]`: `pcs`（鳴らす音の集まり = 種類の型（9 は弾き方の型）＋ベース）、`rh`、`form`（9 の弾き方）、`pair`（音が同じ組のもう一方の読みと段階）、`rows`（行の ID・正解・候補・食い違うか）。`chords2.notes[]` は全部の音（手・高さ・強さ・時刻）。`chords2.variant` に分け・`heldOut`・音色。

## 確かめたこと

- **同じ種で同じ wav**: 4 本（P1＋A、P1＋B、P2、peaky）をキャッシュを空にして 2 回描き、同じハッシュ。値をテストで固定（`render.test.ts`）。
- **正解の時刻 ±1 ms**: 548 本の全部の音（56,875 音）で、音を 1 つずつ部屋に通して測った音の始まりと正解の時刻の差が最大 0.0005 ms（`--check`）。
- **正解の種類 = 描いた音**: 548 本の全部の区間（4,975）で、その区間で弾いた音の高さの集まり（区間の番号でも、時刻でも）が正解の和音の型＋ベースと一致。全部の変化形の楽譜でも同じことを単体テストで確かめる（`voicing.test.ts`）。
- **正解表**: 26 行それぞれがちょうど 1 つの句の X で、調・前・次・ベース・正解・候補・食い違うかが表と合う（元の調と移調の両方、`material.test.ts`）。
- 長すぎて切れた音 0、割れ 0。スパイクのテスト全部（1162 通過、スキップ 45 はドラムのキット B〜D が無いことなど前からのもの）、`tsc --noEmit -p spikes/analysis`、`privacy_check --history --allow-empty` が通った。

## 計画との違い・見てほしい所

1. **ホールドアウトのピアノは sfz ではない**: CC0 の sfz のピアノ（FreePats の Upright Piano KW）は 7z でしか配られておらず、ここには 7z を開く道具が無い。そこで CC0 の WAV と対応表の VSCO にした。KW を使うなら 7z の展開手段を入れる判断が要る。
2. **スパイク 6 の B0〜B3 と既存の L0〜L3・LR・CH はここでは描き直していない**: それぞれの CLI（`render/bass/cli.ts`、`render/cli.ts`）で T7 が作る。B の材料はそれに加えて、この組 B（同じ曲を新しい弾き方・変化で）。
3. **新しい種類の区間が少ない所がある**: 開発の `7sus4`・`madd9` は 2 区間、`add9` は 3 区間（× 変化 5）。§5 の種類ごとの適合率は合成の開発用で見るので、T11 の前に種を足すか（例 開発を種 4〜7 に）を決めたい。
4. 開発用のピアノは調整と同じ P1（ピアノの音色の一般化はホールドアウトの P2 と録音だけで見る）。
5. 音が同じ組の例の句は、行の前後の和音に調を決める和音を 1〜3 個足した（どれを足したかは `material.ts` の `PHRASES`）。句が本物らしく聞こえるかは G1 でユーザーに 2〜3 本聞いてもらう（計画 §8）。
