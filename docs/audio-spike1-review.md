## 確かめて問題がなかったこと

- **解析器は正解を見ていない（構造と実際の両方）**: `analyze.analyze(wav_path, cfg)` は wav のパスと設定しか受け取らない（`analyze.py:24-43`）。`py/dsp/` と `analyze.py` には truth・glob・ファイル名の読み取り・環境変数の参照が無い（grep で確認）。`run_all.py:158-159` は dsp-v1 に wav のパスだけを渡す。`test_analyze.py:105-111` が「wav 以外のファイルを開かない」ことを確かめている。`mode-chord` も wav だけから作る（`baseline.py:66-86`）。
- **加工（`degrade.py`）の正しさ**（使い捨てのスクリプトで実測）: 差分で測った SNR は `l1-noise30` で 30.00 dB、`l2-room` は残響後の信号に対して 20.00 dB。残響ありと元の wav の相互相関のピークは 0 サンプル（遅れなし）。インパルス応答の RT60（Schroeder の積分で T30 から推定）は 0.601 秒（指定 0.6）。ピンクノイズは 1/f のパワー（`degrade.py:61-69`）。はみ出し（割れ）は 0。
- **テンポの揺れの正解**: `truth.ts` は MIDI のテンポ変更から小節ごとに秒を計算し、テンポが小節の頭以外で変わる・`tempoCurve` と違う場合は止まる（`truth.ts:218-262`）。`check_alignment` で、ピアノが毎拍鳴る揺れの変化形 4 本（`full-t116-straight-drift`・`etude-full-…-drift`・`etude2-…-drift`）は音の始まりの中央値 +11〜13 ms・最後の音 +14〜26 ms で OK。
- **本物の録音の拍の当てはめ（`rec_truth.py`）**: 最初の音 ±60 ms・テンポ ±1 % の範囲で、8 分音符の格子に音の始まりがいちばん集まる値を探す（`rec_truth.py:88-110`）。残差の中央値 2.9 ms。等間隔の拍という前提（クリックに合わせた演奏）と合っている。
- **テスト**: TS 153 件（9 ファイル）すべて成功。Python は 137 件中 132 件成功・5 件失敗（R1）。
- **速さ**: 結果に記録された時間の平均は 1 分の音あたり 3.3 秒（最大 4.3 秒）、目標 10 秒以内。うち読み込み＋HPSS が約 77 %（2.5 秒 / 分）。
- **決定性**: 乱数は種で固定（`degrade.py:43-44`）。解析は乱数を使わない。

## まとめ

- 件数: 高 3・中 11・低 5・提案 1。
- **確かめて良かったこと**: 解析器は構造上も実際にも正解を見ていない。加工（雑音の SNR・残響の遅れ 0・RT60）とテンポの揺れの正解は正しい。新しい依存と音色のライセンスは手元で使う分には問題ない。速さは目標の 3 分の 1 程度。
- **数字の読み方で注意すること**:
  - 小節の頭の高い点（L0〜L2 で 0.97〜1.0）は「最初の音 = 小節の頭」という前提がすべての曲で当たっているだけで、規則の力は測れていない（R2）。
  - REC のコード / 拍 0.44 は、解析の弱さより**正解の注記と演奏の食い違い**が主な理由の可能性が高い（R3: 疑わしい 7 小節を除くと 0.87）。拍 F 0.919 も採点の作り物（R5: 余韻の拍を除くと 0.993）。
  - 合成音源は誤りがほぼ無い（コード / 拍 0.99）ので、確信度・7th・取り違えの分析は合成だけでは判断できない（R12・R13）。
- **T12 の調整**: `self_transition` と 7th の値はホールドアウトでも良くなり支持できる。`loudness_weight` 0.25 は根拠が無く、テスト 5 件の失敗（R1）を T15 で必ず解消する。REC 由来の規則は、録音が増えるまで「試し」の扱いにする（R11）。

### スパイク 2 への提案（AI なし、効果の見込みつき）

並びは効果の大きい順。どれも「人が決めた規則と値」で、学習はしない。

1. **REC の正解を「弾いたとおり」に直し、確認の表を作る**（R3）。小節ごとに「その小節・前後の小節の正解」との一致を出し、ユーザーが印の付いた小節だけ聴いて直す。見込み: 今の dsp-v1 のままで REC のコード / 拍 0.44 → 0.8 前後（疑わしい小節を除いた値 0.87 から）。これが無いと、下の 3〜5 の効果を REC で測れない。録音は 3 本以上に増やしてから REC の目標を決める。
2. **小節の頭を正しく測る変化形と、テンポの倍・半分の規則**（R2・R7）。頭を 1〜3 拍切った変化形・弱起の曲と「位相 0 だけ」の比べる相手を足す。テンポは `--tempo`（クリックあり録音）と「T・2T・T/2 のうち、コードの変わり目と低音が拍に乗る割合がいちばん高いもの」を選ぶ規則。見込み: 揺れの変化形の拍 F 0.67 → 0.95 以上。小節の頭は、まず本当の値（`arp8` の確信度がほぼ 0 なので、位相が分からない曲では 25〜50 % 程度かもしれない）が見えるようになる。
3. **半拍ごとのコードの区切り**（2 拍目の裏の変化を表す）。区切りを半拍にし、ビタビ法の「同じコードが続く確率」は半拍に合わせて上げる（例 0.8）。小節の頭が分かっていれば「変わってよいのは拍の頭と裏だけ」に制限する。使い捨ての試しでは、合成の別の音色で 0.961 → 0.992。REC は 1 を終えてから測り直す（今の正解では 0.44 → 0.41 で判断できない）。採点も 8 分音符ごと（R6）にする。
4. **確信度を事後確率にし、`?` の意味を測る**（R12）。前向き・後ろ向き計算で「その拍でそのコードである確率」を出し、L3 と直した REC で「`?` 付きの拍に誤りが集まるか」を見る。見込み: `?` を 29 % から 10〜15 % に減らし、`?` の付いた拍の誤り率が付かない拍の 3 倍以上、を目標にできる。
5. **低音で根音を助ける・メロディを弱める**。低音域のクロマでルートに加点、メロディの音（高い音域で短い音）を弱めるために高い音域は「区間の中央値」でならす。使い捨ての試しでは、今の REC の正解では効果が出なかった（低音の加点 0.44 → 0.36、正解の根音が低音域でいちばん強いのは 24 区間中 5）。左手が根音を弾かない演奏もあるので、1 の後に REC と合成（ベースのある `full`）で比べてから入れるか決める。
6. **小さな直し**: 最後の拍の「コード無し」（R8、全変化形で +0.8 ポイント）、REC の余韻の拍の採点（R5）、`check_alignment` の誤った FAIL（R9）、部分実行で一覧が消える問題（R15）。どれも数行で、スパイク 2 の数字を信じる前に直しておきたい。
