## 1. 「候補だけ」の形（コードで）

- **切り替え**: `D2Values` に `output: 'candidate'` を足す。`'name'`（今の D2）のときはキーを置かないので、今あるハッシュ（`607593f71c46`・`77cc49d1ca67`・`944e04c507d1`・`8b6cd09b7c54`）は変わらない。`'candidate'` のとき θ_c = `theta`、`theta < thetaLow` を許す（`resolveChords2Config` の検査をこの場合だけゆるめる）、`switchPenalty` は 0 に固定（使わない）。
- `'candidate'` のとき `analyze.ts` は V0 の列を**書き換えない**（`applyD2` の改名と HMM を通らない）。だから区間・名前・ベースの印は基準と同じ。
- **対象の区間**: chords2 の区間のうち、種類が 3 和音（`maj`・`min`・`dim`）のものだけ。v1a が出した 7th・`aug`・`sus4`・`dim7`・和音なしには付けない。
- **付ける場所**: chords2 の区間の `chordCandidates`（ベースの段の前）。`toEvalChords` で `candidates` に入り、`bassChords` のクリシェの分割は `...chords[p.src]`（`ts/bass/analyze.ts`）で候補ごと写すので、分けた区間や `/X` の 3 和音（`C/E`）にも付く。並びは `toEvalChords` のとおり top-k より前。
- **列ごとの読み**: 区間の列ごとに、**区間の**ルートと 3 和音で `evalAdded`（T5。θ_low = .3 は分母の「鳴っている」にだけ使う）を呼び `rho` を読む（列の名前ではない。`merge_min_beats` で名前の違う列が混ざるため）。読みは maj → `7`（d 10）か `maj7`（d 11）の強い方（同じなら `7`）、min → `min7`、dim → `m7b5`。**ρ ≥ θ_c** の列がその読みを持つ。
- **区間の候補**: `d2Candidates` の半分の規則（区間の列の半分以上が持つ読み）。足す音の候補は**区間に 1 つまで**。見せるのは今までどおり 2 つまで（`CANDIDATE_CAP`）なので、多くの区間で事後確率の上位の 2 番目が外れる（押し出し。§2 の守りで見る）。画面での並び順は G3 で決める（採点は「見せる候補に入っているか」だけを見るので、順は数を変えない）。
- 新しいコードは「列ごとの読み」の小さな関数と、`analyze.ts` の分かれ道だけ。`'name'` の D2（T7 の値）は「採らない」と書いて切り替えに残す。

- **名前が基準と同じ**（区間の時刻・ルート・種類・`/X`、全ファイル）は線ではなく作りの確かめ。見る前の selftest（調整用 433 本）で 0 を確かめる。見る時点で 0 でなければ作りの誤り（決定 10 の CQT の共有を含む）なので、結果は使わずメインに返し `harness-fix` として扱う。
- 計画 §5 の E1 の決め手（名前の適合率・再現率）は名前に足す形のためのもの。候補だけでは名前が動かないので使わない（線を下げたのではなく、測る出力が変わった）。
- **天井**（`s8-dev-1` の基準の行から、見た後の集計。道具 `eval/s8ceiling.ts`、`7087fc1`）: 足す音の候補で直せるのは、基準で名前を直す必要があり、候補でも直せず、正解が E1 の種類で、主な出力の区間がルートの合う同じ仲間の 3 和音（`/X` は問わない）の続きだけ。
  - 録音 ALL: 正解の拍 640、続き 227、届く続き **16** → 天井 **2.50 / 100 拍**（a〜f 3・g〜j 13）。−1.5 には約 10 続き（6 割）が要る。
  - SYN: 正解の拍 12,592、続き 3,970、届く続き **420** → 天井 **3.34 / 100 拍**。−1.5 には約 189 続き（4.5 割）が要る。
  - どちらも天井は線より上だが、録音は届く続きの 6 割を当てる必要がある（7 / maj7 の取り違えと押し出しは天井に入れていない）。
- **手で直す数の区間**（T7b に書く）: 単位は `editCounts` の正解の続き（`segmentUnits` ではない）。`ScoreOptions.onRun`（`7087fc1`）で続きごとに（手数、拍）を取り、率は和の比、組は（ファイル、続きの番号）。名前と区間は基準と同じなので、差は −Δ`nameFixableByCandidate` だけで、続きごとに「直せる」の 0 / 1 で足りる。「続きごとの Δ の和 = `editCounts` の差」を試験で確かめてから使う。
