# M7 Google Drive への保存・読み込み: 決定事項

スケッチ: Claude Design キャンバス「band-sheets Drive 保存（M7）」（https://claude.ai/artifact/2M2aEXmUjKRpm46WsnYaX5）

## これまでの決定（requirements.md・m3-decisions.md）

- 保存先は個人の Google Drive。スコープは `drive.file`（アプリが作った・開いたファイルだけ）。
- 編集中の内容は localStorage に自動で下書き保存し（`band-sheets:draft:<songId>`）、Drive のファイルを書き換えるのは「保存」などの明示的な操作のときだけ。
- 曲の一覧画面は M7 で Drive の状態も含めてスケッチしてから作る。

## ユーザー判断（2026-10-06）

- **保存場所**: マイドライブに専用フォルダ「band-sheets」を自動で作り、曲はすべてそこに置く。曲の一覧はそのフォルダの中身。
- **共有**: M7 は自分だけ（自分の PC とタブレットで同じ曲を使えればよい）。バンドの仲間との共有は後で考える。
- **保存の衝突**: PC とタブレットで別々に直して保存がぶつかったときは、「Drive の方が新しくなっています」と知らせ、上書きするか Drive の方を読み直すかを選ばせる。
- Google Cloud の OAuth クライアント ID の作成はユーザーが行う（手順は M7 の途中で渡す）。
- 実装の前に Claude Design でスケッチ（曲の一覧、ログイン、保存・読み込み、衝突）を作り、合意してから進める。

## スケッチ確認（2026-10-06）

- スケッチの内容で進める。
- **保存の衝突の選択肢は 3 つ**: 上書きする／Drive の方を読み直す（手元の変更は別の曲として残す）／Drive の方を読み直す（手元の変更は捨てる）、とキャンセル。
- **端末名は自動**（ブラウザの情報から「PC」「iPad」など）。一覧に最後に保存した端末として出す。
- **Drive のファイル名は曲名と連動**（曲名を変えるとファイル名も変える）。曲の区別は内部の ID で行い、別の端末でも混乱しないようにする。
- タブレットの閲覧画面から編集には入れない（PC で編集・タブレットで閲覧の方針どおり）。
- 通信が遅い・つながらないときは、前回取得した一覧と曲を先に出す。
- 一覧の並び順の初期値は「更新が新しい順」。
- 閲覧だけのときは下書きを作らない（編集を始めたときだけ作る）。

## ファイル形式と拡張子（2026-10-06）

- `.chordpro` を名乗るなら ChordPro の仕様から外れてはいけない。一方で、今後の機能拡張のため形式は ChordPro に寄せなくてよい（今の「ChordPro コンテナ＋alphaTex パート」の独自形式を続け、必要なら広げてよい）。
- そのため **拡張子は独自に定義する**（`.chordpro` は使わない）。中身はテキスト（UTF-8）のまま。
- 拡張子は **`.bandsheet`**（例: `きらきら星.bandsheet`）。Drive の mimeType は `text/plain`。
- 計画の確認事項（2026-10-06）: ログインしていないときも「この端末だけ」の印付きで曲を一覧に出す／端末名は自動だけ／衝突の画面は違う行の数だけ出す／実際の iPad での確認は公開（HTTPS）後／未保存の変更がある曲を「閲覧で開く」ときは注意付きで下書きを出す。
