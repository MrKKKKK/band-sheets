## 気づいたこと

1. **M3 は録音の `/X` の点のルートを一番上げる**（.277 → .470、線 .477 の直前）。+4（`C/E` を `Em`）を 43.5 → 25 点に減らした。しかし**誤った `/X` が録音で .078**（e〜f .158、g〜j .106）に増え、名前は上がらない（.581）。和音を選び直した後で付く `/X` が、正解の 3 和音（`/X` なし）の上にも付くため。
2. **M1・M2 は名前を上げる**（録音 .627 / .618、合成 B2 .715 / .751、L まとめ .861 → .95）が、**LR の後戻りが大きい**（.806 → .674 / .606）。LR はスパイク 0/2 の左手 5-1-5'-1 の形だけで、R2 のとおり本物の録音にはこの形が無い。
3. M2 は合成の `/X` の点のルートを大きく上げる（B1 .202 → .506、B .870）が、録音ではほぼ上げない（.310）。合成と本物の違いが一番大きい方法。
4. 手で直す数は、録音では M3 だけが線を通る（22.0 → 19.9）。合成ではどの方法も通らない。
5. 「7th を 3 和音に読む」誤り（`7→maj`・`m7→m`）は B の方法では変わらない（G1 の決定 10 のとおり記録の列）。

## 決定（G2、2026-11-22、ユーザー）: 案 A

**M1〜M3 は 1 つも採らない**。アプリに入るのはスパイク 6 の bass の設定（`appBassConfig()` = G2 既定から `redecideRoot` を切ったもの、`77cc49d1ca67`）のまま。方法は切り替えとして残す（`config.ts`・`bass.ts` に「採らなかった」と書いた）。理由: 通った線は M3・M1 が 5 本、M2 が 6 本（11 本中）で、参考の G2 既定も 5 本、全部を通った方法は無い。線は結果を見る前に決めたので、それに従った。M1 は名前を上げる方法（録音 .627）、M3 は `/X` のルートを上げる方法（.277 → .470）として記録し、持ち越す。順の問題（組の規則と B）は T10 で「bass の印の後」と決めた（`pipeline.ts`）。
