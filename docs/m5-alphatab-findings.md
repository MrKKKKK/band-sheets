# M5 alphaTab 1.8.4 調査結果（連符・シャッフル・パーカッション）

M5（ドラム編集画面）の計画の前提として、alphaTab 1.8.4 の alphaTex 構文と実際の読み込み・描画結果を検証した。
検証方法: `node_modules/@coderline/alphatab/dist/alphaTab.core.mjs`（alphaTex importer の実装）と `alphaTab.d.ts` を読み、
Node から `alphaTab.importer.AlphaTexImporter` を直接呼んで多数の alphaTex 断片を読み込み、`Beat`/`Note`/`MasterBar` の
実際の値（`hasTuplet`/`tupletNumerator`/`tupletDenominator`/`playbackDuration`/`tripletFeel`/`isGhost`/`accentuated` など）を確認した。
さらに Storybook の一時ストーリー（検証後に削除済み）で `PartScore`（alphaTab 本体のレンダリング）を実際にブラウザで描画し、
スクリーンショットで見た目を確認した。調査用スクリプトは `.scratch-alphatab/`（検証後に削除済み）に置いた。ソースコードの変更は行っていない。

## 1. 連符（tuplet）

構文: 音符の直後・デュレーション（`.N`）の前後どちらでもよいビート効果 `{tu N}` または `{tu N D}`（N=分子/連符の音数、D=分母/本来の拍数）。

| 検証項目                                             | 結果                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{tu 3}`（単一引数、省略形）                         | 動作する。3 連符として `tupletNumerator=3, tupletDenominator=2` が設定される（3 個で本来2個分の時間）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `{tu 5}`                                             | 動作する。`5/4`（5個で本来4個分）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `{tu 6}`                                             | 動作する。`6/4`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `{tu 7}`                                             | 動作する。`7/4`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `{tu 5 4}`（分子+分母の明示形）                      | 動作する。結果は `{tu 5}` と同一（5/4）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `{tu 11}` / `{tu 11 8}`                              | **動作する**（11連符、`11/8`）。alphaTab のソース中には単一引数 `tu` の許可値リストに `3,5,6,7,9,10,12` のみが載っている箇所があるが、実際のパーサはこの検証を素通りし、`11` も含めて任意の値を受理した（ソース上の制限表記と実際の動作が一致していない alphaTab 側の実装の揺れ）。分子・分母を明示する `{tu N D}` 形式なら、組み合わせの制約は事実上ない。                                                                                                                                                                                                                       |
| 8分・16分・4分音符上の `{tu 3}`                      | いずれも動作する（ベースのデュレーションに対する比率が変わるだけ）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **毎拍への `{tu N}` の必要性**                       | **要・毎拍に書く必要がある（最初の1拍だけでは不十分）。** 最初の拍にだけ `{tu 3}` を書き、残りの拍に書かなかった場合、2拍目以降は `hasTuplet=false` の通常デュレーションに戻ってしまい、小節の時間が合わなくなる（実測: 8分音符3つの想定で `320+480+480` ticks になり、3連符としてもストレートとしても破綻する）。全拍に repeated して書いた場合のみ、全拍が `hasTuplet=true` の正しい短縮デュレーション（各320ticks、合計960ticks=通常の8分音符2個分）になる。**「先頭だけ書けばグループ全体に効く」という想定は誤り。シリアライザは連符内の全拍に `{tu N}` を書く必要がある。** |
| グループの開始・終了、`* N` のような繰り返し短縮記法 | 存在しない。alphaTex には「前のビートの効果を N 回繰り返す」記法はない（`*` はGP形式の小節リピートの話で、拍の連符指定とは無関係）。したがって冗長でも毎拍書くしかない。                                                                                                                                                                                                                                                                                                                                                                                                          |
| 入れ子の連符（triplet of triplets 等）               | 専用構文は見つからなかった。同じ `{tu 3}` を異なるデュレーション（8分・16分）の隣接拍に連続して書くことはできる（動作はする）が、これは「入れ子」ではなく単に拍ごとに独立した連符指定を並べているだけで、ネストした連符グループという概念はソース上存在しない。                                                                                                                                                                                                                                                                                                                   |
| 通常音符と連符の混在する小節                         | 動作する（連符3拍＋通常4分音符3拍など、1小節内に混在可）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 連符内の休符                                         | 動作する。休符は小文字 `r`（大文字 `R` はパーカッション音名として誤認識されエラーになる）。`r.8{tu 3}` のように休符にも `{tu 3}` を毎拍つける。                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 連符＋付点                                           | 動作する。`{tu 3 d}` のように同じ `{}` 内に `tu 3` と `d`（付点フラグ、別のビート効果）を空白区切りで並べて書ける（1つの `{}` に複数のビート効果トークンを列記できる）。                                                                                                                                                                                                                                                                                                                                                                                                          |
| 連符が小節線をまたぐ                                 | 動作する（エラーにならない）。各小節の拍に `{tu 3}` を書けばそのまま小節をまたいで連符として解釈される。                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| パーカッションの同時打ち `(HH BD){tu 3}`             | 動作する。コード（`(...)`）に対して1つの `{tu 3}` を付ければ、その拍の全ノートに連符が適用される。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 小節の時間不足チェック                               | **alphaTab はしない。** 連符を毎拍に書かず小節の合計デュレーションが拍子に対して不足していても、importer はエラーも警告も出さずに読み込む（`readScore()` が正常終了する）。小節の整合性チェックは自分たちで行う必要がある（M4 のメロディと同様、`barTicks`/`splitAtBars` 相当の検証をドラムでも実装する）。                                                                                                                                                                                                                                                                       |

## 2. シャッフル / triplet feel

小節メタデータ `\tf <value>`（または数値 0〜6）。

| 検証項目                                 | 結果                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 受理される値                             | `none`/`no`/`notripletfeel`、`triplet16th`/`t16`/`triplet-16th`、`triplet8th`/`t8`/`triplet-8th`、`dotted16th`/`d16`/`dotted-16th`、`dotted8th`/`d8`/`dotted-8th`、`scottish16th`/`s16`/`scottish-16th`、`scottish8th`/`s8`/`scottish-8th`。数値 `0`〜`6`も対応（0=none, 1=triplet16th, 2=triplet8th, 3=dotted16th, 4=dotted8th, 5=scottish16th, 6=scottish8th）。 |
| 単位                                     | **小節単位**（`MasterBar.tripletFeel`）。                                                                                                                                                                                                                                                                                                                          |
| 次の小節への持続                         | **持続する。** 一度 `\tf triplet8th` を書くと、以降の小節もその値を引き継ぐ（新しい `MasterBar` 生成時に前の小節の `tripletFeel` をコピーする実装を確認）。別の値（`none` を含む）を次の小節で書けば、そこから上書きされる。                                                                                                                                       |
| 描画                                     | 小節の先頭に「♪=♪♪(3)」のような、2符点/3連符の対応関係を示す小さなピクトグラム（スウィング比の説明グリフ）が1度だけ描画される（値が変わった小節の先頭のみ）。スクリーンショットで確認済み。                                                                                                                                                                        |
| 音符のデュレーション・連符フラグへの影響 | **なし。** `\tf` は演奏・表記上の「フィール」情報のみで、ビートの `duration`/`dots`/`hasTuplet` などは一切変化しない。実際にシャッフル感のある譜割り（例: ドット付き8分＋16分）にしたい場合は、`\tf` を書くだけでは符割りは変わらず、音符自体をそのリズムで明示的に書く必要がある。                                                                                |

**結論（M5 の決定事項「シャッフルは音価で表さずShuffle表記で表す」との関係）**: `\tf triplet8th` 等は一般的な楽譜の「Shuffle」表記（スウィング比ピクトグラム）そのものであり、採用した方針に合致する。ドラムエディタでは普通の8分音符をそのまま入力させ、`\tf` だけを小節（またはパート開始時）にトグルで設定すればよい。実際の譜割り変更は不要。

## 3. パーカッションの詳細

パーカッション譜面は `\instrument percussion`（＋通常 `\clef neutral`）で設定する。音名は2つの方法がある。

### 方法A: カスタム別名（本プロジェクトの現行方式）

`\articulation NAME MIDI` で任意の別名をGM系の既知IDに結び付ける。`MIDI` 引数は「GM percussion note number」ではなく、alphaTab内部の既知 `InstrumentArticulation.id` 一覧に含まれる値である必要がある（実際には多くがGMパーカッションノート番号と同じ値になっている）。本プロジェクトの `DRUM_ARTICULATIONS`（`src/lib/partsToAlphaTex.ts`）の全値（HH=42, SD=38, BD=36, CR=49, RD=51, HO=46, T1=48, T2=45, FT=41）は実在の既知IDであることを確認した（存在しない値を渡すとエラーになる）。

### 方法B: `\articulation defaults`

GuitarPro 7 由来の既定名一式をまとめて登録する。各既定名は「読みやすい名前」と「英数字のみに正規化した識別子（スペース・括弧・ハイフン除去、小文字化）」の両方が音名として使える。調査で確認した主要な名前（読みやすい名前 → 正規化id）:

| 用途                                     | 読みやすい名前                | 正規化id（そのまま音名として使える）                                                         |
| ---------------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------- |
| スネア 通常打                            | Snare (hit)                   | `snarehit`                                                                                   |
| スネア サイドスティック                  | Snare (side stick)            | `snaresidestick`                                                                             |
| スネア リムショット                      | Snare (rim shot)              | `snarerimshot`                                                                               |
| ハイハット クローズ                      | Hi-Hat (closed)               | `hihatclosed`                                                                                |
| ハイハット ハーフオープン                | Hi-Hat (half)                 | `hihathalf`                                                                                  |
| ハイハット オープン                      | Hi-Hat (open)                 | `hihatopen`                                                                                  |
| ハイハット ペダル                        | Pedal Hi-Hat (hit)            | `pedalhihathit`                                                                              |
| バスドラム                               | Kick (hit) / Kick (hit) 2     | `kickhit` / `kickhit2`                                                                       |
| ハイタム〜フロアタム                     | High Tom (hit) 等             | `hightomhit`, `midtomhit`, `lowtomhit`, `verylowtomhit`, `highfloortomhit`, `lowfloortomhit` |
| ライド エッジ/ミドル/ベル/チョーク       | Ride (edge/middle/bell/choke) | `rideedge`, `ridemiddle`, `ridebell`, `ridechoke`                                            |
| クラッシュ（high/medium、通常/チョーク） | Crash High (hit/choke) 等     | `crashhighhit`, `crashhighchoke`, `crashmediumhit`, `crashmediumchoke`                       |

（コンガ・ボンゴ・ティンバレス・カウベル・タンバリン・ウッドブロック等のラテン/民族パーカッションも多数登録されるが、MVPのドラムキットでは使わない見込み。）

実測で `ridebell`・`crashhighhit` は単独音名として問題なく読み込めることを確認した（`snaresidestick`・`kickhit` も同様に動作するはずで、誤記の `sidestick`/`kick` だけがエラーになった＝正規化idの厳密な綴りが必要）。

### ステップ記号（ゴースト・アクセント・フラム相当）

| 効果                               | 構文                                                                                         | 位置の注意                                                                                                                                                                    | 確認結果                                                                                                                                                                                                     |
| ---------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| 通常アクセント                     | `{ac}`                                                                                       | 同上（音名の直後）                                                                                                                                                            | `accentuated=Normal`。描画は符頭の上に細いアクセント記号。                                                                                                                                                   |
| 強いアクセント                     | `{hac}`                                                                                      | 同上                                                                                                                                                                          | `accentuated=Heavy`。描画は太い/大きいアクセント記号（通常アクセントと視覚的に区別される）。                                                                                                                 |
| テヌート                           | `{ten}`                                                                                      | 同上                                                                                                                                                                          | `accentuated=Tenuto`。                                                                                                                                                                                       |
| コード内の個別ノートへの付与       | `(HH SD{g}).8`                                                                               | 括弧内の各ノート名の直後に付ける                                                                                                                                              | 動作する。コード内の片方のノートだけにゴーストを付けられる。                                                                                                                                                 |
| グレースノート（フラムに近い効果） | ビート効果 `{gr}`（`{gr onbeat}`/`{gr beforebeat}`/`{gr bendgrace}`、省略時は `beforebeat`） | デュレーションの後ろ（通常のビート効果の位置）                                                                                                                                | ソースのみ確認（実行検証は省略）。専用の「フラム」記号ではなく「拍前のグレースビート」として実装されている。ドラムのフラムらしい見た目にするには、本来の拍の直前に短い同音のグレースビートを置く運用になる。 |

**重要な位置ルール**: ノート単位の効果（`g`/`ac`/`hac`/`ten` など、`noteProperties` 側）は**音名の直後**、デュレーショントークン（`.N`/`:N`）より前に書く。これに対し、ビート単位の効果（`tu`/`d`/`gr`/`txt` など、`beatProperties` 側）は**デュレーションの後ろ**（これまでの `melody.ts` の `.N` glued 仕様と同じ位置）に書く。両方を混ぜる場合、例えば「ゴーストノートで3連符の1拍目」は `SD{g}.8{tu 3}` のように、ノート効果は音名側、ビート効果はデュレーション側、と書き分ける必要がある。これは既存の `CLAUDE.md` の「`.N` glued to a pitch is sticky」の注記と対になる、新しいgotchaとして追記が必要。

## 4. 動かなかったもの / 誤解だったもの

- `SD.8{g}`（デュレーションの後ろにノート効果を置く） → パースエラー（`Unrecognized property 'g'`）。ノート効果は音名の直後に置く必要がある。
- `{tu 3}` を連符の最初の拍にだけ書く → 2拍目以降が通常デュレーションに戻ってしまい、小節の時間が合わなくなる（エラーにはならないが誤ったタイミングになる）。
- 大文字 `R` を休符として使う → パーカッション音名として解釈されエラーになる。休符は小文字 `r`。
- `\staff{percussion}` のような行 → 存在しない構文（`Unrecognized property 'percussion'`）。パーカッション指定は `\instrument percussion` のみで良く、`\staff` 行は不要（既存の `partsToAlphaTex.ts` の実装と一致）。
- ソースコード中の `tu` 単一引数の許可値列（`3,5,6,7,9,10,12`、`11`が抜けている）はドキュメント的な記載に過ぎず、実際のパーサはこの検証を行わない。`tu 11` も `tu(11)`（括弧付きの新記法）も問題なく通った。

## 5. ドラムエディタ向けに推奨する alphaTex サブセット

- 連符: `{tu N}` を**連符内の全拍**に明示的に繰り返して書く。N は 3,5,6,7 など任意（分子・分母が必要な非標準比は `{tu N D}` で明示）。シリアライザ（M4の `melodyTex.ts` 相当）はこのルールを前提に実装する。
- 休符: 小文字 `r`（大文字禁止）。
- シャッフル: 小節頭に `\tf triplet8th`（8分主体なら）または `\tf triplet16th`（16分主体なら）。前の小節から持続するので、パート開始時に一度設定すれば以降の小節に効く。オフにするときだけ明示的に `\tf none` を書く。音符自体は普通の8分/16分のまま変えない。
- パーカッション音名: 既存の `DRUM_ARTICULATIONS`（カスタム別名方式）を維持する。`\articulation defaults` は使わず、既存の短い別名（HH/SD/BD/CR/RD/HO/T1/T2/FT）を使い続けるのが読みやすさ・既存コードとの整合性の面で優れている。
- ゴースト/アクセント: `NAME{g}.N` / `NAME{ac}.N` / `NAME{hac}.N`（音名の直後、デュレーションの前）。
- 同時打ち: `(HH BD).N`、個別のノート効果は `(HH BD{g}).N` のように括弧内の対象ノートの直後に。
- フラム: 専用記号なし。`{gr}`（グレースビート）で近似するか、MVPでは対応を見送る判断もあり得る（別途ユーザー判断が必要）。

## 6. メロディモデルへの影響（M4 で連符を編集可能にする場合）

- `melody.ts`/`melodyTex.ts`/`melodyParse.ts` の既存の連符は「読み取り専用」扱いだったが、編集可能にする場合は上記の「毎拍 `{tu N}` が必要」という制約をモデルの検証ロジック（`splitAtBars` 相当）に組み込む必要がある。1拍だけ `{tu N}` を落とすと小節の整合性が壊れるため、UIが連符の一部だけを編集・削除できないようにする（連符グループ単位での操作にする）ガードが要る。
- ノート効果とビート効果の位置の違い（§3末尾）は、メロディのスラー (`slur "<id>"`) ・タイなどノート単位の効果にも関係する。連符＋スラー、連符＋タイのような組み合わせをパース・生成する際は、効果の種類ごとに glued 位置が異なることをパーサ/シリアライザの両方で踏まえる必要がある。
- 小節の時間不足を alphaTab 自身は検出しないため、連符を含む小節の検証はこれまで通り自分たちの `barTicks`/`splitAtBars` 側で行う（alphaTab の許容度に依存しない）。

## 7. ブラウザでの描画確認

一時的な Storybook ストーリー（`PartScore` を使用、検証後削除）で、パーカッショントラックに 3・5・6・7連符、`\tf triplet8th` のシャッフル表記、ハイハットのクローズ/オープン、クラッシュのアクセント、スネアのゴーストノート、強いアクセントを含む譜面を実際にレンダリングし、`docs/m5-alphatab-check.png` としてスクリーンショットを保存した。

確認できたこと:

- 1〜4小節目: 3・5・6・7連符がブラケットと数字（3/5/6/7）付きで正しく描画される。
- 5小節目冒頭: `\tf triplet8th` のスウィング比ピクトグラム（8分音符=8分音符+16分音符の3連符、のグリフ）が1回だけ描画される。
- 5小節目の音符: アクセント（細い記号）、ゴーストノート（符頭が丸括弧で囲まれる）、オープンハイハット（符頭上に小さい丸）とクローズハイハット（丸なしの×符頭）、強いアクセント（太い記号、通常アクセントと視覚的に区別できる）がすべて見分けられる形で描画された。

## 8. M5 計画前の追加検証（T1）

`docs/m5-plan.md` の設計判断を固める前に、計画で前提にしている alphaTex の書き方・alphaTab 1.8.4 の実際の挙動を再度ピンポイントで検証した。
検証方法は §1〜7 と同じ：Node から `alphaTab.importer.AlphaTexImporter`（`initFromString` + `readScore()`）を直接呼び、`Beat`/`Note`/`MasterBar`/`TupletGroup` の実際の値を確認した（スクリプトは `.scratch-alphatab/check.mjs`、検証後に削除済み）。
描画確認は `PartScore` を使った一時 Storybook ストーリー（`src/components/PartScore/PartScore.t1check.stories.tsx`、検証後に削除済み）を `storybook dev` で起動し、Playwright でスクリーンショットを撮った（`docs/m5-t1-check.png`、保存済み）。ソースコードの変更は行っていない。

### 8.1 ノート効果とビート効果の同居（連符あり）

| 検証項目                                                                                          | 結果                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SD{g tu 3}`（`.N` なし、1 つの `{}` にノート効果+ビート効果）                                    | パース成功。`hasTuplet=true, tupletNumerator=3, tupletDenominator=2`、1 拍目のみ `isGhost=true`。残り 2 拍は `SD{tu 3}` だけで同じ `hasTuplet` になる。                                                                                                                                                          |
| `SD{g}.8{tu 3}`（ノート効果は `.8` の前、ビート効果は後ろ）                                       | パース成功。`SD{g tu 3}` と**完全に同じ結果**（`hasTuplet=true, tupletNumerator=3`, 1 拍目 `isGhost=true`）。`.N` の有無・位置に関わらずどちらの書き方でも同じモデルになる。                                                                                                                                     |
| `SD.8{g}`（ノート効果を `.8` の後ろに置く）                                                       | **パースエラー**（`Unrecognized property 'g'`）。既存の findings §4・CLAUDE.md の gotcha（ノート効果は音名の直後、ビート効果はデュレーションの後ろ）が連符ありでも変わらず成立することを再確認した。                                                                                                             |
| `(HH SD{g}){d tu 3}`（同時打ち、個別ノート効果+コード全体のビート効果）                           | パース成功。`hasTuplet=true, tupletNumerator=3, dots=1`。HH は `isGhost=false`、SD だけ `isGhost=true`。コード内の個別ノート効果と、コード全体にかかるビート効果（`d`・`tu`）が問題なく共存する。                                                                                                                |
| `(SD){tu 3}`（単一楽器でも括弧記法 + 連符）                                                       | パース成功。`(HH SD){tu 3}` と同じ扱いで `hasTuplet=true, tupletNumerator=3`。単一楽器を括弧で囲んでも問題ない。                                                                                                                                                                                                 |
| `C4{tu 3 lyrics "x" slur "A-1"}` → 次の音 `D4{tu 3 slur "A-1"}`（メロディ、連符+歌詞+スラー同居） | パース成功。`hasTuplet=true, tupletNumerator=3`。`beat0.lyrics=['ki']`、`beat0.notes[0].isSlurOrigin=true`（`slurDestination` 参照あり）、`beat1.notes[0].isSlurDestination=true`（`slurOrigin` 参照あり）。連符・歌詞・スラーの 3 つが 1 つの `{}` 内で問題なく共存し、スラーの起点・終点も正しくリンクされる。 |
| `C4.8{tu 3}`（`.N` glued + ビート効果）                                                           | パース成功。`SD{g}.8{tu 3}` と同様、`hasTuplet=true, tupletNumerator=3`。                                                                                                                                                                                                                                        |
| `{tu 13 8}`（13 連符、分母明示）                                                                  | パース成功。13 個の 32 分音符すべてが `hasTuplet=true, tupletNumerator=13, tupletDenominator=8`。拍子 4/4 に対し 13×32 分 = 4 分音符 1 つ分（`tupletDen` の想定どおり）で小節の整合性も壊れない。                                                                                                                |

**結論**: m5-plan.md の設計判断（§1 冒頭）「`.N` glued の直後の `{}` に拍の効果 `tu`/`d` だけがある形」「ノート効果は音名側、ビート効果はデュレーション側」という書き分けルールは、連符が絡んでも全く変わらずそのまま成立する。歌詞・スラー・連符を 1 つの `{}` に同居させる書き方（メロディの連符対応、設計判断2）も実際に機能することを確認した。

### 8.2 同じ N の連符が 2 つ連続したときの括弧

alphaTab のソース（`Beat.finishTuplet()` → `TupletGroup.check()`）を確認したところ、**連符のグループ化はレンダリング時のヒューリスティックではなく、`readScore()` の時点でモデルに組み込まれている**: 拍ごとに `tupletGroup` が設定され、`check()` は `beats.length === tupletNumerator` になった時点で `isFull=true` にしてそのグループを閉じ、次の拍からは自動的に新しい `TupletGroup` インスタンスが開始される。

実際に `SD{tu 3}` を 6 拍連続で書いた場合（8分音符 3 連 ×2）:

- `beat0`〜`beat2` → 同一の `tupletGroup`（`beats.length=3`, `isFull=true`）
- `beat3`〜`beat5` → **別の** `tupletGroup`（`beats.length=3`, `isFull=true`）
- `group0 === group3` は `false`（完全に別オブジェクト）

スクリーンショット（`docs/m5-t1-check.png`、3 小節目）でも、6 拍の `{tu 3}` が「3」ラベル付きのブラケット 2 つとして独立して描画されることを視覚的に確認した（1 つの「6」ブラケットにはならない）。

**結論**: m5-plan.md の設計判断1「alphaTab の括弧のまとめ方（`TupletGroup.check`: 同じ長さの拍なら n 個で閉じる）と完全に一致し、読み込み時の区切りも一意になる」は**ソースコードと実測の両方で正しいことが確認できた**。モデル側にグループ境界の情報を自前で持たせなくても、alphaTab 側が `tupletNumerator` 個ごとに正しく区切ってくれる。

### 8.3 `\section "A"` の直後の `\tf`、シャッフル表示の節ごとの切り替え

| 検証                                                                               | 結果                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `\section "A"` → `\tf triplet8th` → `:8 ...`（8 拍、通常の推奨パターン）           | 問題なくパースされ、8 拍すべて正しく読める。`MasterBar.tripletFeel=2`（triplet8th）、`section.text="A"`。**swallow は発生しない**。                                                                                                                                                                                                                   |
| `\section "A"` → 裸の音名 `HH`（`:N` なし）→ 次行 `:8 ...`（既存 gotcha の再確認） | 既知のとおり swallow が発生：`section.text` が `"A"` ではなく **`"HH"`**（裸の音名が section の第 2 引数として飲み込まれる）になり、1 小節目の拍数も 1 拍だけになる。CLAUDE.md の既存 gotcha が連符検証とは無関係に今も成立することを再確認した。                                                                                                     |
| `\section "A"` → `\tf triplet8th` → 裸の音名 `HH`（`:N` なし）→ 次行 `:8 ...`      | **swallow は発生しない**（`section.text="A"` のまま）。`\tf` はそれ自身の引数（`triplet8th`）を消費して独立したディレクティブとして扱われるため、section の第 2 引数スロットには干渉しない。ただし裸の `HH` 自体は相変わらず「`:N` なしのデフォルト（4 分音符）1 拍」として読まれる点は変わらない（§ gotcha の「`:N` を省略しない」はここでも必要）。 |

シャッフル表示の切り替え（スクリーンショット 4 小節目=セクション B 冒頭）: セクション A 側に `\tf triplet8th` のピクトグラム（♪=♪♪(3)）が 1 小節目冒頭に描画され、セクション B 側の `\tf none` 直後の小節冒頭にも**別のピクトグラム（スウィングなしを示す記号）が描画し直される**ことを視覚的に確認した。前のセクションの表示が残ったまま引きずられることはない。

**結論**: `\section "A"` の直後に `\tf` を置く m5-plan.md の設計判断（§1「シャッフルは各セクション本文の 1 行目に必ず `\tf none|triplet8th|triplet16th` を書く」）は安全で、既存の「裸の音名 swallow」gotcha と衝突しない。ただし `\tf` を書いても裸の音名の gotcha 自体がなくなるわけではないので、CLAUDE.md の既存ルール（セクション内の最初の拍は必ず `:N`/`.N` を書く）は `\tf` の有無に関わらず従来どおり必要。

### 8.4 ドラム五線の位置（T1=50 / T2=48 / FT=41 案）

`PercussionMapper.instrumentArticulations`（alphaTab 1.8.4 のソース内蔵テーブル）と、実際に `\articulation <NAME> <ID>` で宣言した上での `AlphaTexImporter` 読み込み結果（`track.percussionArticulations[note.percussionArticulation].staffLine`）の両方で確認した。`partsToAlphaTex.ts` は変更せず、検証用の一時スクリプト／ストーリーの中だけで `\articulation T1 50` / `\articulation T2 48` を明示的に上書きした（他の 7 種は現行の `DRUM_ARTICULATIONS` のまま）。

| 楽器             | 別名→ID（検証に使った値） | alphaTab `staffLine`（上=1、下に向かって増加） | `DRUM_KIT.step` 相当（m5-plan.md の「下の線=0、上の線=8」換算: `8 − staffLine`） |
| ---------------- | ------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| CR（クラッシュ） | 49（現行のまま）          | -2                                             | 10                                                                               |
| RD（ライド）     | 51（現行のまま）          | 0                                              | 8                                                                                |
| HH（クローズ）   | 42（現行のまま）          | -1                                             | 9                                                                                |
| HO（オープン）   | 46（現行のまま）          | -1（**HH と同じ**）                            | 9                                                                                |
| T1（ハイタム）   | **50**（現行48→提案）     | 1                                              | 7                                                                                |
| T2（ミッドタム） | **48**（現行45→提案）     | 2                                              | 6                                                                                |
| SD（スネア）     | 38（現行のまま）          | 3                                              | 5                                                                                |
| FT（フロアタム） | 41（現行のまま）          | 5                                              | 3                                                                                |
| BD（バスドラム） | 36（現行のまま）          | 7                                              | 1                                                                                |

確認できたこと:

- **`8 − staffLine` が `DRUM_KIT.step` の換算式として、上の 9 種すべてで矛盾なく一致した**（m5-plan.md が挙げている最終的な位置「CR 10・HH/HO 9・RD 8・T1 7・T2 6・SD 5・FT 3・BD 1」と完全に一致）。
- 現行の T2=45・FT=41 は両方とも `staffLine=5` で**完全に重なる**ことを実測で再確認した（m5-plan.md の指摘どおり）。
- 提案どおり T1 を 48→50、T2 を 45→48 に変更すると、`staffLine` は T1=1・T2=2・FT=5 となり、**9 種すべてが異なる `staffLine`（CR -2, RD 0, HH -1, HO -1, T1 1, T2 2, SD 3, FT 5, BD 7）** になる。HH と HO だけは意図的に同じ `staffLine=-1`（符頭の形で区別: 通常の×とサークル付き×）で、これは m5-plan.md の「HH・HO 9（同じ位置）」という設計とも一致しており問題ない。
- スクリーンショット（`docs/m5-t1-check.png`、1 小節目: CR RD HH HO T1 T2 SD FT の 8 拍）でも、HH/HO のペア以外は全て異なる縦位置の階段状に描画されることを視覚的に確認した。

**結論**: **T1=50・T2=48・FT=41 の組み合わせで、T3 が期待する「9 種中 8 つが異なる五線位置、HH/HO のみ同位置（符頭で区別）」が実現することをソース・実測・スクリーンショットの 3 通りで確認した。** T3 の `DRUM_ARTICULATIONS` 変更（T1 48→50、T2 45→48）をそのまま進めて問題ない。

### 8.5 計画への影響

- **矛盾・修正が必要な点はなし。** m5-plan.md の主要な設計判断（連符は毎拍 `{tu N}`、ノート効果/ビート効果の書き分け、`\tf` をセクション本文 1 行目に書く方式、T1=50/T2=48 への変更）はすべて実測で裏付けられた。計画どおり T2〜T24 を進めてよい。
- **T3 向けの追加確認事項（軽微）**: `DRUM_KIT.step` は `8 − staffLine` という単純な線形換算で alphaTab の実際の描画位置と一致することを確認した。T3 の実装・テストでこの関係を使って「alphaTab の `staffLine` と一致する」ことを機械的に検証できる（`npx vitest` 側で `AlphaTexImporter` を使った照合テストを書く際の参考式として記録）。
- **T7（メロディの連符）向けの補足確認**: `C4{tu 3 lyrics "x" slur "A-1"}` のように連符・歌詞・スラーを 1 つの `{}` に同居させる書き方が実際に機能し、スラーの起点・終点（`isSlurOrigin`/`isSlurDestination`）も正しくリンクされることを確認した。m5-plan.md §2 の効果の順序（`d t tu lyrics ch slur`）どおりに書けば問題ない。
- **新しい gotcha（CLAUDE.md へ追記の候補、T23 で対応）**: `\section "A"` の直後に `\tf <value>` を置いても、既存の「セクション直後の裸の音名が swallow される」gotcha は解消されない。`\tf` 自身は swallow の対象にならないが、その後に続く最初の拍にはやはり必ず `:N`/`.N` を明示する必要がある（`\tf` を挟んでも「次の裸の音名が食われる」パターン自体は別物として残るので、セクション本文の 1 行目が `\tf`、2 行目の最初の拍に `:N` を書く、という m5-plan.md の想定どおりの書式を徹底すればよい）。
