## 読み方

- **合成**: 知らない音色（C）でも、区間のベースと誤った `/X` は開発用とほぼ同じ所に来た。G2 の設定で、解析の区間の目標（B1 .932、P .827、誤った `/X` .008）を初めてすべて満たした（P .827 は出した印 61 個の上の値で、誤差の幅は約 ±.1。開発用 .752 との差 +.075 はその幅の中。偶然の範囲）。誤った `/X` ≤ 5 % は、既存の LR では調整に使った 11 本の上でしか満たしていない（LR のホールドアウト 4 本は測っていない。外での値は未確認）。崩れたのはクリシェの並び（正解の区間 .875 → .625、v1a .633 → .393）と正解の区間の分数の F（.947 → .849）。音色が変わると、ベースが音階で動く所の読みが弱くなる。B0（ベースだけ）の印が全部外れるのは開発用と同じで、v1a のコード解析の側の性質。
- **決め直し**: ホールドアウトの合成で、初めて正しい和音を 3 つ壊した（直したのは 4）。差し引きのコード名の当たりは +.001 で、効き目はほぼ 0。録音では 1 回だけ働き、正しく直した。
- **録音**: そのままの音では、v1a が 3 割強の点で和音を出さない（R2 と同じ原因 = 音量）。そろえると 0 になり、区間のベースは .992。ベースの段階が出した `/X` は、両方の入力で全部当たった。ただし、そろえた音では v1a がベースの音をルートと読む（`C/E` を `Em` と読む形が、+4 以外の音程にも広がる）。このため、付けられる `/X` は 52 点のうち 1〜2 個しかない。**ホールドアウトの録音では、下書きの `/X` はほとんど出ないが、出したものは正しい**。ネックはベースの段階ではなく v1a のルートの読み。
- 録音は 2 本・出した印 14 個と小さいので、P 1.00 は「誤りが見つからなかった」以上の意味を持たない。

## T15・T16 への申し送り

- 録音の見る回はこれで全部使った（開発用 2 回 + 見る時点 ③）。合成のホールドアウトも使った。**このあと値を変えても、新しい数で確かめる場所は残っていない**。T15 の直しは、構造・道具・文書に限った（T14 の指摘と T15 の対応は計画の「実績」）。
- T16（記録）へ: (1) v1a の和音なしが音量に左右される件（R2・R3 の持ち越し）は、ホールドアウトでも同じだった（.336 → 0）。(2) v1a がベースの音をルートと読む件は、`/X` の再現率を決める一番の要因。決め直し（短三和音で共有の音だけ）では足りない。次に試すなら、v1a のコード解析の側（main、またはベースを引いてからコードを読む将来の展望 §10）。(3) 音色が変わるとクリシェの並びが崩れる。(4) 決め直しが初めて正しい和音を壊した（3 つ）。採用（G2 の決定 2）を見直すかは、ユーザーが判断する材料。(5) 正解の区間の B0 に分けた区間の誤った `/X` が出る（調整用 .020、ホールドアウト .041）。T10 の表は全体の行しか見ていなかった。
- T16 の定義への一言: 「誤った `/X`」の分母には、v1a が和音を出さない点も入る（和音なしが多いと小さく出る。録音のそのままの音で最大 1/(1−.37) 倍ほど甘い。今回は 0 なので結論は変わらない）。開発用の G2 の数は、案 A / B を開発用で見たあとに採ったあとの値。
