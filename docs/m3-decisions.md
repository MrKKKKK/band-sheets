# M3 コード + 歌詞の編集画面: 決定事項

スケッチ: Claude Design キャンバス「band-sheets コード譜エディタ」（https://claude.ai/artifact/RBSzYfyFzZahF7UCUyNyGF）

## ユーザー評価（2026-10-03）

- 3方式とも入力しやすい。キーに合わせてダイアトニックコードが出るのが好印象。
- A（歌詞を貼り付け → 文字をクリックしてコードを置く）: 初心者でも迷いにくい。
- B（ChordPro テキスト + ライブプレビュー）: ChordWiki ユーザーが移行しやすい。
- C（パレットから置くスタンプ方式）: パレットと歌詞が離れていて、今どのコードを選んでいるかを見逃しやすい。パレットの管理機能自体は魅力的だが、視線の移動が大きい。

## 方針

1. **A と B を切り替えて使える**ようにする（裏側は同じ ChordPro テキストなので、切り替えても内容は失われない）。C は採用しない。
2. **B にパレット管理を入れる**: 挿入できるコードをパレットとして管理する。常には表示せず、「＋」ボタンを押したときに管理画面（ポップオーバー）が出る。
3. **パレットは A と B で共通**にし、A のコード入力の小窓に出る候補にも使う。
4. **自分で追加したパレットのコードは曲ファイルに保存する**: `{x_palette: C7(9,13) Fmaj7}`。ChordPro では `x_` で始まるディレクティブは独自拡張用で、ほかのアプリでは無視される。パレットとして表示するのは、この保存分、曲中で使用中のコード、キーのダイアトニックコードの3つを合わせたもの。

## M3 実装計画での確認結果（2026-10-03）

- ダイアトニックは**三和音のみ**（メジャー 7 つ、マイナーは自然的短音階 7 つ + V のメジャー）。セブンスはユーザーが自分でパレットに追加する。
- A の操作でテキストが正規化されるのは許容する（B で入力している間は整形しない）。
- A はセクション名を A, B, C… と自動で付けるだけ。**名前の変更は B で行う**。
- **localStorage は「編集途中の下書き」の置き場として M7 以降も残す**。編集中の内容は常に localStorage に自動保存し、Drive のファイルを書き換えるのは「保存」などの明示的な操作をしたときだけにする（M7 で設計する）。そのため下書きは曲 ID ごとに保存する（`band-sheets:draft:<songId>`）。M3 では曲 ID は固定の `local` だけを使い、画面は1曲の自動保存のみ。曲の一覧画面は M7 で Drive の状態も含めてスケッチしてから作る。
