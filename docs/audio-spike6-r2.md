### R2 で解析の区間が低い理由: v1a の「和音なし」

- 採点の点のうち **.367（188/512）で v1a が和音を出していない**（a .35・b .52・c .27・d .32）。v1a は拍もテンポも合っている（拍の間隔の比 .990〜1.003、拍のずれの中央値 .02〜.04 拍、正解の和音の変わり目 72 か所が全部 1/4 拍以内に v1a の区切りを持つ）。
- **v1a が和音を出した点に限ると、ベースの音は .988（160/162 点）当たる**。`/X` の無い点ではルートが全部当たる（種類の外れ 11.5 点）。`/X` のある点では、v1a のルートの当たりが 22.5/49.5 点。外れはルート +4（`C/E` を `Em` と読む形）12.5、+3 が 5.5、+9 が 4、ほか 5。
- 原因: 録音の音量が小さい。ピーク −19.9〜−22.5 dBFS、RMS −38.6〜−40.9 dBFS で、合成（調整用 B0〜B3 の RMS −20.8〜−23.9）より 17〜19 dB 小さい。v1a の和音なしの判定（`ts/dsp/chords.ts` の `no_chord_energy` 0.02）は、クロマの絶対の大きさで決まる。確かめとして、調整用の合成 16 本（B0〜B3）の音量を下げて v1a を回した（見る時点ではない）。和音なしの割合は 0 / −10 / −18 / −24 dB で .000 / .000 / .132 / .585 になった。本物は、ペダルを踏まない電子ピアノの減衰で、さらに和音なしに落ちやすい（白玉の b が一番多い）。
- これは凍結した v1a の側の性質で、ベースの段階は変えていない。アプリでは、ユーザーのファイルの音量しだいで和音の下書きが抜けることになる（main への持ち越しの候補）。

## 持ち越し（main・次のスパイクへ。このスパイクでは実装しない）

1. **v1a の和音なしの判定が音量に左右される**（`no_chord_energy` 0.02 がクロマの絶対の大きさ）。ライン出力のまま（RMS −39 dBFS 前後）だと、ピアノの録音で 4 割近くが和音なしになり、音量をそろえると 0 になる。直し方の候補: 解析の前に音量をそろえる（R3 と同じ）、または判定を相対の値にする。v1a の出力が変わるので main の判断（固定のテストと既存の合成の点を見直す）。
2. 合成に足す変化（ユーザーの決定: T13 の前には作らない）:
   - **音量の幅**: 一部の変種を本物のライン出力の大きさ（ピーク −20 dBFS 前後、RMS −39 dBFS 前後）で書き出す。これだけで合成の v1a にも和音なしが出る（−18 dB で .13）。
   - **ピアノだけの段階**（ベースの楽器なし）: 左手が C2〜B2 でベースを弾き、ダンパーペダルなし（ユーザーの録り方と同じ）。ブロック・白玉・分散・ルート＋5 度。今の B0〜B3 はいつもベースの楽器があり、決め直しはその音で調整した。本物では決め直しが R2・R3 とも 0 回だった（`C/E` を `Em` と読む外れは残っている）。
   - **弾く時刻の揺れ**: 音の頭のずれの中央値 20〜31 ms に合わせる。
   - **左手がルート＋5 度の形**（d と同じ形）を、分数の無い曲の見張りに足す（LR の 5-1-5'-1 とは別に）。
