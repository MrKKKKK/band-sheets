## 1. 問いと「できた」の意味

**問い**: 12 の音名にたたむ前に、オクターブを残した「どの高さの音が鳴っているか」（倍音を基音に寄せた音の強さ）を求めれば、v1a が 3 和音に読む 7th（`7→maj`・`m7→m`）と、ベースをルートと読む誤り（`C/E` → `Em`）が減るか。足しすぎ（3 和音に 7 度を付ける）を増やさず、予算に収まるか。

値打ち: 録音で一番多い誤りは 7th を 3 和音に読むこと（スパイク 7 の録音 ALL で `m7→m` 28 点・`7→maj` 22 点、`6→maj` 20 点）。`C7`・`Am7`・`CM7` が正しく出れば、ユーザーが 1 つずつ書き足す手間が減る。迷う所は決めつけず候補に出す（候補から選べば 1 手で直る）。

**原因の見立て**（スパイク 7 の結論 1・2）: 12 の音名のクロマでは、ベースとその倍音（`E` の 3 倍音 `B`）が上の音と混ざり、足した 1 音は 3 和音の音の倍音にまぎれて弱い。語彙を広げるだけ（V1）でも、ベース帯域を引くだけ（M1）でも直らなかった。**倍音を基音に寄せれば、ベースの倍音が `Em` を押す分と、7 度が弱く見える分の両方が減る**、がこのスパイクの仮説。ただし寄せ残した倍音は、ちょうど足す音の度数に落ちる（§2.1）。

できた:

- 前段（§2.1）と導き方（§2.2）が `ts/chords2/` の切り替えとして動き、全部切で v1a と同じ出力（固定のテスト）。
- 基準（`appBassConfig()`、`77cc49d1ca67`）と同じ実行で比べた §5 の表が、段階（E1・E2）ごとにある。止めた段階は理由がある。
- ホールドアウトで 1 回確かめた結果と、main への写し方の一覧（§6）・ブラウザでの時間がある。

**やらないこと**: アプリへの組み込み。v1a の値の調整。拍・調の推定を変える。11・13 のテンション、`add9`・`madd9` 以外の add。ピアノ以外の楽器・バンドの音（記録だけ）。

## 2. 方法

### 2.1 前段: オクターブつきの音の強さ（F。決定 1）

**F1 倍音の和＋引く**（最初）: 入力は音名にたたまない半音ごとの CQT（スパイク 6 の `lowCqt.ts` と同じ作り、C1 から 7 オクターブ）を v1a の拍ごとにまとめたもの。拍ごとに:

1. 候補は **C1〜B5**（出力は C2〜B5。C1〜B1 はベースの楽器の低い音の倍音を引くためだけの候補）。倍音の和は h = 1〜8 まで（ピアノの非調和性で高い倍音は半音の箱を外れるので）、届かない倍音は数えず個数でならす。
2. 一番強い候補を採り、その倍音の並びを**なめらかにした包絡の高さまでだけ**引く（共有する倍音を全部は引かない。Klapuri のなめらかさの考え方）。残りがしきい値より小さいか、8 音になったら止める。
3. **幻の音の守り**: 採る候補は、基音の箱か奇数倍音の箱に、倍音の和の一定割合以上の強さがあること（`E3` を `A1` の 3 倍音と読んで `A1` を作らない）。

寄せ残しが足す音に化ける形（試験で固定する。T4）: ルート・ベースの 7 倍音 → 短 7 度（`7`/`m7` の偽物）、3 度の 3 倍音 → 長 7 度（`maj7` の偽物）、5 度の 3 倍音 → 9 度、1/3 の高さの幻の音 → 6 度。

**前段の当たり**（記録。調整用の合成だけなので見る時点を使わない。T4）: 拍ごとの音（オクターブつき・音名）の再現率・適合率、正解の足した音だけの再現率、正解が 3 和音の拍で短 7・長 7・6 度に出た偽の音の割合。**G1 で F2 に進む目安**（前もって固定）: 調整用で「足した音の再現率 < .60、または偽の足す音 > .05」のときだけ。前段がこれを満たして決め手に届かないなら、原因は D2 の側として F2 には進まない。

**F2 決めたノートの型の NMF**（G1 で要るときだけ。T8）: 半音ごとの型で拍ごとの CQT を表し、重みだけを解く。型は調整用・開発用・ホールドアウトのどれにも使っていない音色から作る（P1 から作ると開発用の合成で答えを知った測り方になる）。出どころは決定 11。判定は開発用の録音を主に見る。

### 2.2 種類とベースの導き方（D。決定 2）

**D2 3 和音を決めてから足す音を見る**（主）。スパイク 7 の U1 と同じく、まとめた区間ごとには決めない（`C – C7` やクリシェが 1 区間に潰れるため）:

1. chords2 の V0（v1a の値）の Viterbi の**拍ごとの列**から、ルートと 3 和音の仲間（`7`・`maj7` → maj、`m7` → min、`m7b5` → dim）を取る。`dim7`・`aug`・`sus4` の拍は D2 の外でそのまま。
2. 拍ごとに、音名 p の強さ s(p) = 前段の出力のうち p の音のオクターブの最大。ただし**一番低い検出音（ベース）は分子から外す**（ベースにしか無い音は足さない。スパイク 7 の「ベースにだけある音」の扱い）。
3. 分母 = 3 和音の音のうち鳴っている音（s ≥ θ_low × その拍の最大。ベースも含む）の s の平均。5 度を省いた弾き方で比が膨らまないようにするため。
4. 比 ρ(d) = s(ルート + d) / 分母。E1 は d = 10（短 7）・11（長 7）、E2 は d = 9（6）と、min の d = 11（`mM7`）。ρ ≥ θ なら足す、θ_low ≤ ρ < θ なら候補だけ。短 7 と長 7 は強い方 1 つ。6 と 7 が両方なら 7 を出し 6 は候補。
5. 同じルート・3 和音が続く間で「足す音あり / なし」の 2 状態を小さな HMM（切り替えの罰 1 つ）でならし、足す音つきの名前にしてから区間にまとめ直す（足す音が変われば区間が分かれる）。

**D1**（切り替え 1 つ）: 前段の出力を 12 の音名にたたみ、v1a のクロマの代わりに chords2 の型の点に使う。`C/E` → `Em` の +4 のずれが減るかを見る（決定 4）。ベースの音（`/X`）はスパイク 6 の B-1 のまま（`appBassConfig()`）。
音が同じ組（`C6` / `Am7` など）は D2 ではルートの決め方で決まる。組の規則（`pairRule`）は既定で切、もう一方の読みはいつも候補（スパイク 7 の決定 8 を守る）。

## 6. アプリへの道（スパイクではやらず、一覧だけ作る）

- 採ったら、main へは `chore/<issue>-analysis-sync-<commit>` の写し直しの PR だけ（main §2.1）。前段・導き方と、スパイク 6 のベースの段階を**遅延読み込みの塊**にする（Worker は 56,752 / 60,000 B で空き約 3 KB。ベースの段階だけで +3.4 KB）。`origin.ts` のハッシュと固定のテストを作り直す。
- CQT: ベースの段階は自分で 5 オクターブの CQT を計算する（スパイク 6 T12 でベースの段階全体 +2.81 秒 / 5 分）。F1 の 7 オクターブの CQT を chords2 の中で 1 回だけ計算し、下 5 オクターブをベースに渡せるかを T4 で確かめる（オクターブごとに間引くので値が変わりうる。変わるとベースの出力が `appBassConfig()` からずれる）。変わるなら 2 回計算する（決定 10）。v1a の中の CQT の使い回しは `ts/dsp` を変えるので main で考える。
- 結果の欄: 種類はコード名の文字に入れ、迷った足す音は `chordCandidates`（スパイク 7 と同じ形）。
