## 3. 種類の数・`/X` の点（`npx tsx ts/chords2/recScores.ts`）

「出る小節」= その種類が鳴る小節の数、括弧は鳴る長さ（小節）。ホールドアウトは合計の数だけ。

| 種類                          | 開発用 g〜j | ホールドアウト k〜n |
| ----------------------------- | ----------- | ------------------- |
| `mM7`                         | 8（4）      | 6（3）              |
| `m6`                          | 9（4.5）    | 9（4.5）            |
| `6`                           | 9（5.5）    | 7（5）              |
| `sus2`                        | 6（3）      | 5（2.5）            |
| `7sus4`                       | 7（3.5）    | 8（4）              |
| `add9`                        | 5（3.5）    | 5（3.5）            |
| `madd9`                       | 6（3.5）    | 5（3）              |
| `9`                           | 7（3.5）    | 8（4）              |
| `m9`                          | 8（4）      | 9（4.5）            |
| `maj9`                        | 7（4）      | 6（3）              |
| `/X` の点（1 拍 2 点）        | 60          | 68                  |
| 組 `6/min7`: 全 / 食い違う    | 21 / 4      | 22 / 4              |
| 組 `m6/m7b5`: 全 / 食い違う   | 10 / 2      | 10 / 3              |
| 組 `sus2/sus4`: 全 / 食い違う | 7 / 1       | 7 / 1               |

- **`/X` の点**: ホールドアウト 68 ≥ 60（計画 §3.2。スパイク 6 は 52）。開発用 60。
- **計画の「新しい種類はそれぞれ 8 小節以上」には届かない**。10 種類 × 8 小節 = 80 小節が、1 本 16 小節 × 4 本 = 64 小節（区分ごと）を超えるため、長さでは原理的に無理。数え方を「出る小節」にし、全種類 5 以上（テストの下限）にとどめた。8 に届かないのは開発用 `sus2`・`7sus4`・`add9`・`madd9`・`9`・`maj9`、ホールドアウト `mM7`・`6`・`sus2`・`add9`・`madd9`・`maj9`。これより詰めると、前後の和音（文脈の規則が使う）が無くなり、曲として弾けない。
- **音が同じ組**: 食い違う例は 1 区分 7〜8 個で、`sus2/sus4` は 1 個ずつ。組の当たりは合成（T5 の正解表の例）が主で、録音は記録。

## 4. 録り足しを提案する所

- **G1**（計画の G1 に「録り足し」がある）: 上の不足を理由に、**足りない種類に絞った 2 本（開発用 1・ホールドアウト 1、各 16 小節）**を提案する。1 区分で足りないのは合わせて 10 小節ぶん前後なので、足すと全種類が「出る小節」8 以上になる見込み。R2（見る時点 ①）の新しい種類の区間の数が少なくて表が読めないときは、G1 で強く勧める。
- **G3〜G5**（計画 §3.3）: その段階の決め手の指標（新しい種類の適合率）の 95 % 区間が線をまたぐときに、その段階だけの 2〜4 本。証拠は区間の数と Wilson の幅（`score.ts` の `byQuality`、区間単位）。録音の新しい種類は 1 区分 5〜9 小節なので、区間の数は種類ごとに 10 前後になり、幅は ±.25 くらいになりうる。
