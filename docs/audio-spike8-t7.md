## 1. 格子と選び方（調整用の数を 1 つも見る前に決めて、コミットした）

- **材料**: 調整用だけ（`baseline.ts items()` = `c2-t-*` 312 本（T3 の 7th の弾き方 `-v7*` を含む）、スパイク 6 の B0〜B3 の調整用 72 本、スパイク 0/2 の L0〜L3・LV・LR 49 本）。開発用・ホールドアウト・録音は開かない（`beginLook` は呼ばない）。すべて `prepareInput`（−22 dBFS）。
- **行**: 基準 `base` = chords2 V0（= v1a）+ `appBassConfig()` の印（決定 7。同じ実行で計算）。値の行 = V0 + D2（E1）→ 同じ `appBassConfig()` の印（`marksOnV2`）。F1 の値は T4 のまま（`f1ConfigHash` `cbf11a42c101`）。
- **格子（1 回目）**: θ ∈ {.25, .35, .5, .65, .8} × θ_low ∈ {.2, .3} × 切り替えの罰 ∈ {0, .1, .3}（θ < θ_low は除く）= 27 値。D1 は調整しない（決定 4: 選んだ D2 の値に `octaveChroma` を足した行を見る時点で記録だけ）。
- **選び方**（調整用、どの線も同じ実行の `base` と比べる。SYN = 合成の B・V1〜V3・pair・B0〜B3、Lpool = L0〜L3・LV、ALL = 調整用の合成全部）:
  1. 守りの線で FAIL が少ない順（足しすぎ（正解が 3 和音で `/X` 無しの点、ALL）≤ .03。後戻り: 名前・3 和音の点の名前・ルートだけ（落）が Lpool・LR・ALL で基準 −.01 以上。`/X` の点のルート（落、SYN）が基準 −.02 以上）。
  2. 決め手の線を多く通る順（E1 = `7`・`m7`・`maj7`・`m7b5` をまとめた適合率 ≥ .80、再現率が基準 + .30 以上。SYN）。
  3. 手で直す数 / 100 拍（全、SYN、候補で直せる分を除く）が少ない順。
  4. E1 の再現率（SYN）が高い順。
  - 見張り（7th を 3 和音に読む点の数など）は選び方に使わない。1 位を見る時点の値にする。どの値も守りを通らなくても 1 位を見る時点に出し、そのことを書く（スパイク 7 T10 と同じ扱い。止めるかは G1 でユーザーが決める）。
- **2 回目**（計画の上限は 2 回）: 1 回目の 1 位が守りを全部通り、決め手のどちらかを .05 以内で外すとき（適合率 ≥ .75、または再現率の差 ≥ .25）、または決め手を両方通り守りの 1 本だけを .01 以内で外すときだけ。格子は 1 位のまわり: θ* ± .05（θ ≥ θ_low*）× 罰 ×.5 / ×1 / ×2（罰が 0 なら 0 / .05 / .1）、θ_low = θ_low*（最大 9 値）。選ぶのは 1 回目と 2 回目をまとめた同じ選び方の 1 位。それ以外は 2 回目をしない。
- **見る時点で見る線**（§5。値は見る時点の後に変えない。目標は仮で、結果を見て下げない）: 決め手 = 合成の開発用 SYN の E1 の適合率 ≥ .80・再現率 − 基準 ≥ +.30。守り = 足しすぎ ≤ .03（a〜f と SYN）、後戻り（名前・3 和音の点の名前・ルートだけ、落）は開発用の Lpool・LR で −.01（−.01〜−.02 はユーザーが決める）、録音 ALL で −.02、`/X` の点のルートは録音 ALL と SYN で −.02。見張り = 7th を 3 和音に読む点の数（録音 ALL、決定 9: 基準の半分以下。減らなければ採らない）、手で直す数 −1.5。95 % 区間は区間単位のブートストラップ（正解の区間を引き直す、2000 回）、基準との差は同じ区間の組で引く（`bootstrap.ts pairUnits`）。

## 2. 調整の結果（調整用 433 本、1 回目だけ）

`tune run --round 1` → `tune report --round 1`（出力 `out/chords2-s8dev1/tune1-report.md`）。SYN 384 本・Lpool 38 本・LR 11 本。

| 行（θ / θ_low / 罰） | E1 再現率 | E1 適合率 | 足しすぎ ALL | 名前 落 Lpool / LR | 7th を 3 和音 点 SYN | 手数 全 SYN |
| --- | ---: | ---: | ---: | --- | ---: | ---: |
| 基準 `appBassConfig()` | .068 | .450 | .006 | .861 / .806 | 2,425.5 | 21.5 |
| .25 / .2 / .3（再現率が一番高い） | .377 | .447 | .178 | .649 / .758 | 1,412 | 22.0 |

| .65 / .2 / .3 | .151 | .596 | .010 | .866 / .808 | 2,197 | 22.0 |
| **.8 / .3 / .3（選んだ値）** | .083 | .600 | .005 | .858 / .808 | 2,411 | 21.7 |

- **決め手に届く値は 1 つも無い**: 適合率は最大 .600（.80 に遠い）、再現率の差は最大 +.31（θ .25・θ_low .2・罰 .3。ただし適合率 .447・足しすぎ .178 で守りを 7 本落とす。再現率の差の線を通ったのはこの 1 値だけ）。
- **守りを全部通る値も無い**: 足しすぎは θ ≤ .5 で .07〜.18（線 .03）、θ ≥ .65 で .005〜.022。θ ≥ .65 では LR の「3 和音の点の名前」が基準から −.011〜−.017（−.01〜−.02 はユーザーが決める帯）で 1 本落ちる。
- **選び方の 1 位 = θ .8・θ_low .3・罰 .3**（守りの FAIL 1 本（LR の 3 和音の点の名前 −.017、ユーザーが決める帯）、決め手 0/2、手数 21.7）。基準とほとんど同じ出力（再現率 .083 対 .068）。`config.ts T7_E1_D2_VALUES` に入れた。
- **2 回目はしない**: 条件（1 位が守りを全部通る）を満たさない。計画 §5 の止める目安（2 回まで調整しても決め手・守りが届かない）に当たる見込みが高いことは、見る時点の前から分かっている。
- 見張り（選び方には使わない）: 調整用の合成でも「7th を 3 和音に読む点」は一番ゆるい値で基準の .58 倍までしか減らない（決定 9 の線 .5 に届かない）。
- **HMM の区切れ**（T5 の問い、数だけ。同じルート・3 和音のまま足す音が入れ替わる境目 / そのうち正解の 1 区間の中）: 選んだ値 SYN 10 / 10（境目 4,443 のうち）、LR 7 / 7、Lpool 0。θ .5・罰 .1 で SYN 22・Lpool 36・LR 10、θ .25・罰 .3 で SYN 104・Lpool 195・LR 37（どれも全部が正解の 1 区間の中 = 正解に無い区切れ）。値をゆるめるほど増えるが、境目全体の 0.2〜15 % 。
