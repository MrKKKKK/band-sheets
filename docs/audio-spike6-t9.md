- 採った設定の確かめ: `cli.ts --all --split tuning`（コミット `ef34602`、失敗 0）→ `baseline.ts`、`root_regression.ts` ＋ `py/tools/bass_root_regression.py`。
- 設定: ベース入のハッシュ **`3bea9f3db99d`**（T8 は `9b8d16cf12cb`）、既定・切は `254af76bfe61`（T8 は `dfed4fc0704f`）。`config.test.ts` の固定を意図して書き換えた。ベースが切の出力は今までどおり v1a と同じ（`analyzeWithBass` が `analyze` をそのまま呼ぶ。固定のテストは変えずに通る）。

## ① 5 度の誤った `/X`（採った）

規則（`slash.ts`）: ルートの完全 5 度のベース（6/4 の和音）は、確信度が `fifthMinConfidence` 以上のときだけ「転回」にする。下回るときもペダル（先に見る）と経過（次に見る）にはなれる。和声で 6/4 が単独で立つのはまれで、ふつうはペダル・経過・終止の形で出る、という考えに沿う。左手 5-1-5'-1 のパワーコードでは、鳴っている一番低い音が本当に 5 度でも、譜は分数でない。

`fifthMinConfidence` の表（調整用。F は分数の F、誤りは誤った `/X` の割合）:

| 値         | LR の誤った `/X` | 正解の区間 F（全体 / B1 / B2） | 解析の区間 P / F（全体） | 5 度の正しい印（解析の区間 / 正解の区間） | 5 度の誤った印（解析の区間 / LR） |
| ---------- | ---------------- | ------------------------------ | ------------------------ | ----------------------------------------- | --------------------------------- |
| 0（T8）    | .104             | .893 / .921 / .912             | .819 / .239              | 17 / 52                                   | 5 / 47                            |
| 0.2        | .059             | .889 / .921 / .912             | .819 / .239              | 17 / 50                                   | 5 / 25                            |
| 0.3        | .043             | .889 / .921 / .912             | .819 / .239              | 17 / 50                                   | 5 / 15                            |
| **0.4**    | **.034**         | **.886 / .921 / .903**         | **.817 / .236**          | **15 / 49**                               | **5 / 9**                         |
| 0.5        | .032             | .877 / .903 / .894             | .828 / .232              | 14 / 45                                   | 2 / 8                             |
| 0.6        | .031             | .870 / .903 / .885             | .830 / .228              | 13 / 42                                   | 1 / 7                             |

- **0.4 に決めた**: LR の誤りが下限（ペダル・経過以外の 5 度を全部切った .031）から .005 以内に入る一番小さい値で、正解の区間の F は T8 から .01 以内（.893 → .886）。T6 の `minConfidence` と同じ決め方。
- **失った正しい印**: 解析の区間で 2 個（5 度の正しい印 17 → 15。うち 6 個は転回から経過に変わって残った）、正解の区間で 3 個（52 → 49）。G1 で許した「最大 14 個」より少ない。経過に落ちて残るのが効いた。
- 調整用の解析の区間の 5 度の誤った印は 5 のまま（0.5 以上で減るが、正しい印も減る）。LR では 47 → 9（転回 3・経過 1・ペダル 5）。
- **切った 5 度は候補に残す**: 印の無い和音に `bassCandidates: [{ bass: 'G', confidence: 1 }]` を書く（`heldFifths`。`bass` と `text` は v1a のまま、欄は増やしていない。`confidence` は「一番よい点に対する比」で、切った 5 度は一番よい読みだったので 1）。画面で 1 回の操作で `C/G` に戻せる。

## ② B3 の「正解が分数なのにルートを出す」（採らなかった）

正解の区間の取り逃がしの内訳（①の後、各レベル 106 の正しい `/X`）:

| 理由                           | B0  | B1  | B2  | B3  |
| ------------------------------ | --- | --- | --- | --- |
| B-1 がルート（2 位が正解）     | 0   | 1   | 2   | 14  |
| B-1 がルート（2 位も違う）     | 0   | 0   | 0   | 2   |
| 確信度がしきい値より低い       | 0   | 1   | 2   | 7   |
| 規則で説明できない（6 度など） | 11  | 11  | 11  | 12  |
| B-1 がほかの音                 | 0   | 0   | 1   | 0   |

B3 の 16 個のうち 14 個は 2 位が正しいベース。B3 はピアノの左手がルートを 1 オクターブ下で重ね、スマホの低音の弱りもあるので、ルートが 2 つの楽器から点を集める。試した 2 つ:

| 試したこと                                                                                 | 正解の区間 B3 の F               | 解析の区間 P（全体）             | LR の誤った `/X`                 | 判定     |
| ------------------------------------------------------------------------------------------ | -------------------------------- | -------------------------------- | -------------------------------- | -------- |
| ①だけ（採った形）                                                                          | .769                             | .817                             | .034                             | –        |
| 倍音の重み h ごとに ×d（d = .9 / .8 / .7 / .6 / .5）                                       | .775 / .775 / .748 / .742 / .744 | .824 / .823 / .812 / .809 / .738 | .044 / .083 / .139 / .185 / .188 | 採らない |
| 倍音の重み（上を重く、d = 1.15 / 1.3）                                                     | .769 / .758                      | .788 / .763                      | .039 / .036                      | 採らない |
| B-1 がルートで 2 位の比 ≥ r なら 2 位を出す（規則で説明できるときだけ、r = .95 / .9 / .8） | .780 / .775 / .788               | .798 / .744 / .611               | .140 / .191 / .445               | 採らない |

- 倍音の重みを軽くすると、上の倍音を集めにくくなり 5 度・オクターブの読みが増え、LR の誤りが大きく増える。B3 の取り逃がしはほとんど減らない（14 → 15〜17）。
- 2 位を出すと、分数の無い曲でも 2 位（ピアノの 3 度など）が出て、LR の誤りが 14〜45 % になる。目的 1（適合率を重く見る）に反する。
- B3 のこの取り逃がしは「ピアノがルート、ベースが `/X`」の本当にあいまいな所で、印の付いた和音の `bassCandidates` に 2 位が残る（T7）のと同じく、候補として扱うのが合う。印の無い和音に 2 位を候補として書くかは画面を作るときに決める（T7 の申し送りのまま）。

## ③ その他

## T10 への申し送り

- 開発用の合成では解析の区間の適合率が .732（目標 .80）。T10 の後にもう一度見るなら 4 回目のログになる（G1 の決定は T9 の終わりの 1 回だけ。足すかはユーザーに聞く）。
- 調整用で届かないのは B1 の区間のベース（.912）と解析の区間の再現率（.138）。どちらも v1a のルート（ベースの音をルートにする、平行調の取り違え、ウォーキングの細かい区間）が元で、T9 の規則では動かない。
- 短 3 度の印の誤り（上の ③）は、ルートの決め直しを入れた後にもう一度数える。
- 5 度の印は、確信度 0.4 未満なら経過・ペダルだけ。クリシェで区間を分けると前後のベースが変わり、ペダル・経過の判定が増える（5 度の印が戻る）かもしれないので、LR の誤った `/X` を T10 でも出し直す（`t9_sweep.ts` で LR と調整用を同時に見られる）。
- B3 の「2 位が正しい」14 個は候補として残っている（印のある和音の `bassCandidates`）。印の無い和音の 2 位をどう見せるかは画面の話。
- 片付けの候補（変えていない）: `segment.method` / `stayProb`、`segment_eval.ts` と `cli.ts` の開発用ログの重なり。
