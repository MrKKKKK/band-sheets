# M7 Google ドライブを使うための準備（ユーザー作業）

band-sheets が自分の Google ドライブに曲を保存できるように、Google Cloud で「OAuth クライアント ID」を 1 つ作ります。所要時間は 15〜20 分ほどです。お金はかかりません（請求先アカウントの登録は不要です）。

作るもの:

- Google Cloud の **プロジェクト**（band-sheets 用の入れ物）
- **Google Drive API** の有効化
- **OAuth 同意画面**（ログインのときに出る「band-sheets が … を求めています」の画面の設定。自分だけが使う「テスト」状態）
- **OAuth クライアント ID**（種類は「ウェブ アプリケーション」）

最後にクライアント ID をアプリの設定ファイルに貼り付けて、開発サーバーを再起動します。

> 画面の名前について: Google Cloud コンソールの画面は時々変わります。下の名前は 2025〜2026 年の画面（「Google Auth Platform」という名前になった版）に合わせていますが、少し違うことがあります。迷ったら画面上部の検索欄に、手順に書いたキーワードを入れてください。見つからないところがあれば、そこで止めて知らせてください。

## 1. プロジェクトを作る

1. ブラウザで https://console.cloud.google.com/ を開き、曲を保存したい Google アカウントでログインします。
   - 初めてなら利用規約への同意を求められるので、国（日本）を選んで同意します。
2. 画面左上のプロジェクト名の欄（「プロジェクトを選択」または今のプロジェクト名）をクリック → 右上の **「新しいプロジェクト」** をクリックします。
3. 「プロジェクト名」に `band-sheets` と入力します。「場所」は「組織なし」のままで構いません。
4. **「作成」** を押します。数秒で作られます。
5. 画面左上のプロジェクト名の欄が `band-sheets` になっていることを確認します（なっていなければ、欄をクリックして `band-sheets` を選びます）。**以下の手順はすべてこのプロジェクトを選んだ状態で行います。**

## 2. Google Drive API を有効にする

1. 画面上部の検索欄に `Google Drive API` と入力し、出てきた **「Google Drive API」**（マーケットプレイス / API）を選びます。
   - または左のメニュー「APIとサービス」→「ライブラリ」で `Google Drive API` を検索します。
2. **「有効にする」** を押します。「API が有効です」「管理」と表示されれば完了です。

## 3. OAuth 同意画面（Google Auth Platform）を設定する

1. 左のメニュー「APIとサービス」→ **「OAuth 同意画面」** を開きます（検索欄に `Google Auth Platform` と入れても開けます）。
2. 「Google Auth Platform はまだ構成されていません」と出たら **「開始」**（Get started）を押し、次の 4 つの段階を順に入力します。
   1. **アプリ情報**: 「アプリ名」に `band-sheets`、「ユーザー サポートメール」に自分のメールアドレスを選んで「次へ」。
   2. **対象**（Audience）: **「外部」**（External）を選んで「次へ」。
      - 「内部」は Google Workspace の組織用なので、個人の Gmail アカウントでは選べません。
   3. **連絡先情報**: 自分のメールアドレスを入力して「次へ」。
   4. **終了**: 「Google API サービス: ユーザーデータに関するポリシー」に同意するチェックを入れて「続行」→ **「作成」**。
3. **テストユーザーに自分を追加する**: 左のメニュー **「対象」**（Audience）を開きます。
   - 「公開ステータス」が **「テスト中」**（Testing）になっていることを確認します。**「アプリを公開」は押しません**（自分だけで使うので、テストのままにします）。
   - 下の「テストユーザー」の **「+ Add users」**（ユーザーを追加）を押し、曲を保存する自分の Google アカウントのメールアドレスを入力して **「保存」** します。
   - テスト中のアプリは、ここに追加したアカウントしかログインできません（最大 100 人）。
4. **スコープ（アプリが使ってよい範囲）を追加する**: 左のメニュー **「データアクセス」**（Data Access）を開きます。
   - **「スコープを追加または削除」** を押します。
   - 一覧の上のフィルタに `drive.file` と入力し、**`.../auth/drive.file`**（説明:「このアプリで使用する Google ドライブ内の特定のファイルのみの参照、編集、作成、削除」のような文）にチェックを入れます。
     - よく似た `.../auth/drive`（ドライブのすべてのファイル）や `drive.readonly` は**選ばないでください**。band-sheets はアプリが作ったファイルだけを使います。
   - 下の **「更新」** を押し、画面の一番下の **「Save」**（保存）を押します。
   - `drive.file` は「機密性の低いスコープ」に分類されるはずです（「機密性の高いスコープ」の欄に入っていなければ OK）。テスト中は Google の審査は不要です。

## 4. OAuth クライアント ID を作る

1. 左のメニュー **「クライアント」**（Clients）を開き、**「+ クライアントを作成」**（Create client）を押します。
   - 古い画面では「APIとサービス」→「認証情報」→「+ 認証情報を作成」→「OAuth クライアント ID」です。
2. 「アプリケーションの種類」で **「ウェブ アプリケーション」** を選びます。
3. 「名前」に `band-sheets (local dev)` と入力します（自分が見分けるためだけの名前です）。
4. **「承認済みの JavaScript 生成元」** の **「+ URI を追加」** を押し、次の 2 つを 1 行ずつ追加します（末尾に `/` を付けない、パスを付けない）:
   - `http://localhost:5173`
   - `http://127.0.0.1:5173`（ブラウザのアドレス欄が `127.0.0.1` になる場合のための予備）
5. **「承認済みのリダイレクト URI」は空のままにします**（band-sheets はポップアップでログインするので使いません）。
6. **「作成」** を押します。
7. 「OAuth クライアントを作成しました」の画面に **クライアント ID**（`123456789012-xxxxxxxxxxxxxxxx.apps.googleusercontent.com` のような長い文字列）が出ます。これをコピーします。
   - あとからでも「クライアント」の一覧で `band-sheets (local dev)` を開けば見られます。
   - **クライアント シークレットは使いません**。コピーも保存も不要です（band-sheets はサーバーを持たない作りで、シークレットを使わない方式でログインします）。シークレットはどこにも貼らないでください。
   - クライアント ID はパスワードのような秘密の値ではありません（ログインの画面で誰でも見られるものです）。とはいえ、band-sheets ではリポジトリに入れない設定ファイルに置きます。
8. 生成元の設定が反映されるまで、**5 分〜数時間かかることがあります**。すぐにログインして「redirect_uri_mismatch」や「origin_mismatch」「許可されていない JavaScript 生成元」のようなエラーが出たら、しばらく待ってから試してください。

### ポート番号 5173 について

- band-sheets の開発サーバー（Vite）は `http://localhost:5173` で動きます（devcontainer が 5173 番をホストに転送しています）。Google のログインは**登録した生成元と完全に同じアドレス**からしか動かないので、M7 の実装で「5173 番が使われていたら別の番号にずらす」のをやめ、起動に失敗するようにします（`strictPort`）。開発サーバーが 2 つ動いていないか気をつけてください。
- ブラウザのアドレス欄に `http://localhost:5173` と表示されていることを確認してください（`5174` などになっていたらログインできません）。

## 5. 将来、公開（静的ホスティング）するときに追加すること

今はまだ不要です。MVP の後でアプリを `https://<公開先のアドレス>` に公開するときに:

1. 「クライアント」→ `band-sheets (local dev)`（または公開用に新しく作ったクライアント）を開きます。
2. 「承認済みの JavaScript 生成元」に公開先の生成元（例: `https://example.github.io`。パスは付けない）を追加して保存します。
3. 必要なら「ブランディング」（Branding）の「承認済みドメイン」に公開先のドメインを追加します（求められたときだけ）。

補足:

- Google のログインは `http://localhost`（と `127.0.0.1`）か **HTTPS** のアドレスからしか使えません。そのため、iPad から PC の開発サーバーに `http://192.168.x.x:5173` のようにつないでもログインはできません。**実際の iPad での確認は公開後**になります（M7 では PC のブラウザで、タブレットの画面サイズで確認します）。
- 自分以外（バンドの仲間）にも使ってもらうときは、テストユーザーに追加するか、アプリを「本番」に公開する必要があります（共有は M7 の範囲外）。

## 6. クライアント ID をアプリに設定する

1. band-sheets のフォルダ（VS Code で開いているフォルダの一番上）に、**`.env.local`** という名前のファイルを作ります（すでにあれば開きます）。
2. 次の 1 行を書きます。`=` の右に、手順 4 でコピーしたクライアント ID をそのまま貼ります（引用符や空白は付けない）:

   ```
   VITE_GOOGLE_CLIENT_ID=123456789012-xxxxxxxxxxxxxxxx.apps.googleusercontent.com
   ```

3. 保存します。
   - `.env.local` は `.gitignore`（`*.local`）でリポジトリに入らない設定になっています。
   - M7 の実装で、書き方の見本 `.env.example`（値は空）をリポジトリに入れます。
4. **開発サーバーを再起動します**（`.env.local` は起動したときにしか読まれません）。
   - VS Code の「コンテナーで再度開く」で開いているなら: `npm run dev` を動かしているターミナルで **Ctrl+C** を押して止め、もう一度 `npm run dev` を実行します。
   - ホストのターミナルから動かしている場合: 動いているターミナルで Ctrl+C で止めてから、`docker exec -it -u node -w /workspaces/band-sheets band-sheets npm run dev` をもう一度実行します。
5. ブラウザで `http://localhost:5173` を開き直します。ログインの画面に「Google でログイン」ボタンが出ていれば設定が読まれています（「Drive は設定されていません」と出る場合は、ファイル名・変数名・再起動を確認してください）。

## 7. 本物で確かめる（M7 の最後、U1）

実装が終わったら、次の順に試して結果を知らせてください。

1. 「Google でログイン」を押します。ポップアップが開きます（開かなければ、アドレス欄の右のポップアップのブロックを解除）。
2. 自分のアカウントを選びます。**「Google はこのアプリを確認していません」** という警告が出ます。テスト中の自分のアプリなので、**「続行」**（または「詳細」→「band-sheets（安全ではないページ）に移動」）を選びます。
3. 「band-sheets が Google アカウントへのアクセスを求めています」で、**「このアプリで使用する Google ドライブ内の特定のファイルのみの参照、編集、作成、削除」**のような 1 項目だけが出ていることを確認して「続行」を押します。
4. 新しい曲を作って「保存」を押します。https://drive.google.com/ の「マイドライブ」に **「band-sheets」フォルダ**ができ、中に曲名のファイルがあることを確認します。
5. 別のブラウザ（またはシークレットウィンドウ）で `http://localhost:5173` を開いてログインし、同じ曲が一覧に出ること、開いて少し直して保存できることを確認します（これをタブレットの代わりにします）。
6. 元のブラウザで、更新せずに同じ曲を直して保存し、**「Drive の方が新しくなっています」** のダイアログが出ることを確認します。
7. アカウントのメニューから「ログアウト」します。

## うまくいかないとき

| 表示・症状                                                                                           | 考えられる原因                                                                                                           |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 「アクセスをブロック: このアプリのリクエストは無効です」「redirect_uri_mismatch」「origin_mismatch」 | 生成元の登録が `http://localhost:5173` と違う（`https`・末尾の `/`・ポート番号の違い）か、反映待ち（手順 4-8）           |
| 「アクセスをブロック: band-sheets は Google の審査プロセスを完了していません」                       | ログインしたアカウントがテストユーザーに入っていない（手順 3-3）                                                         |
| ポップアップがすぐ閉じる・開かない                                                                   | ブラウザのポップアップのブロック、またはサードパーティ Cookie の制限。アドレス欄の表示からこのサイトのポップアップを許可 |
| 「Drive は設定されていません」                                                                       | `.env.local` の場所・変数名 `VITE_GOOGLE_CLIENT_ID` の綴り・開発サーバーの再起動                                         |
| ログインはできるが保存で失敗する                                                                     | Google Drive API を有効にしていない（手順 2）、または別のプロジェクトで有効にした                                        |

## テスト中の注意（7 日で許可が切れる）と公開

- 公開ステータスが「テスト」のあいだは、**許可が 7 日ほどで切れます**。切れると Google の同意画面がもう一度出るので、同じ手順で許可し直してください（曲のデータや下書きは消えません）。
- これが面倒なら、OAuth の同意画面（「Google Auth Platform」→「対象」）で **「本番環境に公開」** にできます。band-sheets が求めるのは `drive.file`（このアプリが作ったファイルだけ）だけで、Google は `drive.file` を「機密性の低い（non-sensitive）スコープ」に分類しています（https://developers.google.com/workspace/drive/api/guides/api-specific-auth ）。ただし、公開したあと「確認されていないアプリ」の警告が残るかどうか・どこまで確認が必要かは、画面の案内に従ってください（こちらでは確認できていません）。
- `.env.local` は `.gitignore`（`*.local`）で除外済みなので、うっかりコミットされません。
- 自動テスト（e2e）は偽の Google を使い、**ポート 5174** の専用サーバーで動きます。5173 で動かしている開発サーバーには影響しません（本物の Google にはつながりません）。

## わからないところ（確認が必要な点）

- コンソールのメニュー名（「Google Auth Platform」「対象」「データアクセス」「クライアント」など）は 2025 年以降の画面に基づいています。英語表示・日本語表示で名前が違うことがあり、日本語の訳は推測を含みます。
