# スパイク 5 T12: S-拡張（新しい楽器と叩き方）

読む人: ユーザー（S-拡張の結果を見て、録音で何を確かめるかを決める人）と、R3・T13 以降の担当。
目的: T12 で足した S-拡張の判定の方法、新しい楽器と叩き方の種類ごとの表、S-9・S-3 が変わっていないことの確認、大きさ・速さ、録音でしか分からないことを 1 か所にまとめる。

## 評価の方法

- 実行: HEAD `a2bad31` の上の T12 の変更（コミットは報告に）、設定 `drum-v0` ハッシュ `29e9d1cb07c2`（T11b は `88d18eb37af0`。`ext` の群を足した）。**ホールドアウト（キット C）と開発用（キット B）は走らせていない。**
- 素材は調整用だけ。今までの `ext` の型（種 1〜3・11〜13、D1・D2 だけ）は S-拡張の打点が少ない（キット A のスプラッシュ 4 打・チャイナ 2 打など）ので、**調整用の素材を足した**: 型 `ext2`（`render/drum/patterns.ts`）、種 21〜26、キット A・D・H、D1・D2 の 36 本（`variants.ts` の `DRUM_SETS` に記録）。小節ごとにキットにある種類（クロススティック・ペダル HH・ライドのベル・カウベル・スプラッシュ・チャイナ）を 1 つずつ順に叩く。正解の時刻は全打点（3,392）が ±1 ms 以内（最大 0.000 ms）、クリップ無し。今までの 570 本は変わらない（golden のテストが通る）。
- 種類ごとの表は `ext` と `ext2` の 54 本（キット A・D・H 各 18 本）を **S-ext で分類だけ**（`classify_eval.ts --level S-ext`、打点を合わせて数えた F50）。LOPO（T10 と同じ: キット A の素材を別のプリセット 16 Power・24 Electronic・25 TR-808 のテンプレートで判定）も同じ。
- 正解の打点の数（54 本の合計）: キット A は SP 44・CN 28・CB 116・SD.xs 68・RD.bell 128・HH.foot 58、キット D は CN 67・RD.bell 274、キット H は CN 34・CB 118・SD.xs 74・RD.bell 156。キット D にはスプラッシュ・カウベル・クロススティックが無く、H はスプラッシュとペダル HH を外している（`DRUM_SAMPLES.md`）。
- **リムショット（SD.rim）とフットスプラッシュ（HH.fsp）は調整用のどのキットにも無い**（B・C だけ）。測れないので判定も作っていない。

## S-ext の方法（S-9・S-3 の出力は変えない）

`classifyOnsets(..., level = 'S-ext')` は S-9 の打点を作った後に `ext.ts` の `extHits` で打点ごとに書き換える（手順 7）。根拠は 2 つ:

- **テンプレートの票**: S-9 の金属の判定と同じ NMF（タムの合わせ込みの前）の、S-拡張の列（CB・SD.xs・RD.bell・SP・CN。T6 から吸収の列として入っている）の活性。
- **キットに依らない「鳴りの高さのそろい方」**: タムの窓（打点の 10 ms 後から 80 ms、`toms.ts` の FFT を使い回す）の 300〜8,000 Hz で、いちばん大きい山 ÷ 中央値（`tonal`）とその周波数。ベルとカウベルは 1 つの強い山で鳴る（調整用: カウベル 約 85 倍・470 Hz、キット D・H のベル 45〜55 倍・1.6〜3.7 kHz）。シンバル・HH・SD は 5〜25 倍。タムは高いが 400 Hz 未満。

規則:

| 種類                | アプリでの基の楽器 | 規則                                                                                                                                                                                                                                      |
| ------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| スプラッシュ SP     | CR                 | S-9 の CR で、広がりながら鳴っていない（減り方 ≤ +0.5 dB）とき、CR・SP・CN の票の中で SP が 8 割以上                                                                                                                                       |
| チャイナ CN         | CR                 | 同じく CN が 8 割以上                                                                                                                                                                                                                     |
| カウベル CB         | RD                 | CB の列が活性の 2 割以上、または tonal ≥ 40 で 400〜1,500 Hz かつ速く減る（< -8 dB）、タムが無い。足す。その打点の S-9 の HH・HO・RD は消す                                                                                                 |
| ライドのベル RD.bell | RD                 | S-9 の RD で、ベルの列が金属の活性の 3 割以上。または S-9 の RD・HH・HO で tonal ≥ 35 かつ 1,500 Hz 以上（未知のキットのベルは速く減るので S-9 では HH になる）                                                                        |
| クロススティック SD.xs | SD               | SD.xs の列が活性の 3 割以上で、その打点の金属が CR でない（キット D・H のチャイナが A のクロススティックに似る）。S-9 の SD を置き換えるか、足す                                                                                       |
| ペダル HH HH.foot   | HH                 | ペダル HH のテンプレート（キット A の 44 番、`templates.ts` の新しい群 `extFoot`。S-3・S-9 の NMF には入れない）を足して解き直し、その列が 4 割以上なら S-9 の HH・HO を置き換える（金属が無い打点には足す）                               |
| リムショット・フットスプラッシュ | SD・HO | 出さない（調整用のサンプルが無い）                                                                                                                                                                                                         |

置き換えた打点は、基の楽器を 2 番目の候補（`alts`）に入れる。アプリの譜面（`toDrums.ts`）には今までどおり書かない（数えて捨てる）。

- LOPO のプリセットはシンバル・カウベルがキット A と同じサンプルなので、スプラッシュ・チャイナ・カウベルの LOPO は「既知」に近い。**未知のシンバルで見られるのはキット D・H のチャイナだけで、取れない**（D・H のチャイナはキット A のスプラッシュ・クロススティックの票が多い）。票の割合 5 割では D・H のチャイナが SP になった（余計な SP が D 48・H 45 打）ので 8 割にした（D 3・H 18 打）。チャイナはそのまま CR になる。

## S-9・S-3 が変わっていないこと

- 分類だけ（今までの調整用の素材 A 種 1〜3・D と H 種 11〜13、LOPO 16/24/25、`--level S-9`）: T11b の表と全部同じ値（例 キット A D2: CR .911・RD .905・HH .984・HO .894・T1 .931・T2 .935・FT .945・SD .949・BD .970）。キット D のタムも .713・.721・.713 のまま（G2 の決定 3 の目安を満たすまま）。
- 通し（`cli.ts --all`、キット A 種 1〜3 の 114 本）: S-3・S-9 とも、出した譜面（`.tex`）が T11b と **114 本すべてバイト単位で同じ**。S-3 の D1 HH .948・D2 HH .939・D2 SD .925 も同じ。§5 の S-9 の目標（キット A D2、タム・シンバル類 ≥ .80、HH・HO ≥ .75）は満たしたまま。
- テンプレートの表（`templates.ts`）はペダル HH の 2 列を足しただけ（前の 28 列は同じ値）。足した列は S-3・S-9 の NMF に入らない。

## 大きさ・速さ

- Worker（`drumBench.vite.config.ts` のビルド、gzip -9）: T11b 29,949 B → T12 **31,264 B**（+1.3 KB: ext.ts とペダル HH の 2 列）。枠 35 KB の中。Worker はまだ S-3 で動かしている。
- Node（devcontainer、D2 の 30 本、2 回）: 音声 1 分あたり、キット A は S-3 約 910 ms・S-9 約 1,050 ms・**S-ext 約 1,340 ms**、キット D は S-3 約 1,070 ms・S-9 約 1,370 ms・**S-ext 約 1,610 ms**。増えはペダル HH のための NMF の解き直し（打点ごと）。§5 の速さ（1 分あたり 3,000 ms）の中。

## 録音（R3）でしか決められないこと

- リムショット・フットスプラッシュ: 合成に無い。aD5 の録音に入っていれば、まず S-9 で何になるか（SD・HO か）を記録する。
- ペダル HH: テンプレートだけの判定なので、ユーザーのキット（aD5 の音源）の音で取れるかは録音でしか分からない。
- チャイナ・スプラッシュ: 未知のシンバルでは取れない（キット D・H のチャイナは 0）。ユーザーが叩くかどうかも含めて録音で。
- ライドのベル・カウベル: tonal の規則（キットに依らない）が本物の音で効くか。
- G2 で決めた「S-拡張のどれが自分の曲に要るか」（§8）は、ユーザーが答える。

## 持ち越し

- 未知のシンバルのチャイナとスプラッシュの見分け（調整用にスプラッシュが 1 種類しか無い）。
- ベルの票を S-9 の HH に使うと未知のキットのベルは取れるが、普通の HH を壊す。HH をベルにしない形を選んだ。
